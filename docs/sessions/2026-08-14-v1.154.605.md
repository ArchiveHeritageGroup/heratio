# v1.154.605 (2026-08-14)

fix(discovery): stop defaulting the discovery connection to the atom database. ResolvesDiscoveryConnection (DiscoveryController, PageIndexService) and RefreshFacetCacheCommand both fell back to 'atom' when discovery_db_connection was unset. That database exists only on an install overlaying AtoM, so on a Heratio-native instance every discovery read failed with 'Access denied ... to database atom' - the same root cause as the authority-function-sync fix in v1.154.604. Both now fall back to the application's own default connection, which is what the setting's own in-code documentation already said it was for ('every install builds facets from its own data; only heratio pins this to atom'). Pinning to atom remains available and is unchanged wherever it is set explicitly - dev and sasa resolve to their own connection, heratio.org keeps atom - so this alters nothing on existing instances and only stops a fresh self-contained install breaking
