# v1.154.523 (2026-08-05)

fix(theme): theme-CSS regeneration no longer fails silently (footer colour save). Two hardening changes after diagnosing a client report that saved colours (esp. the footer) don't take. (1) Cache-busting: nginx serves the static /css/ahg-theme-dynamic.css with a 7-day max-age, so a saved colour wouldn't show for up to a week; master.blade now appends ?v=<filemtime> to the dynamic-css link, so each re-save forces a fresh fetch (no hard-refresh needed). (2) Write-failure surfacing: regenerateThemeCss() now returns the paths it could NOT write and both theme-save callers flash a WARNING instead of a false saved - under hardened php-fpm (ProtectSystem=full) public/ is read-only, so the generated CSS silently did not regenerate and the footer kept its old value while the header (applied live/inline) updated. The warning tells the operator to grant ReadWritePaths for public/css + public/vendor/ahg-theme-b5/css. Verified: homepage emits the versioned link; regenerateThemeCss returns [] on a writable host.
