# v1.154.723 (2026-09-08)

chore(deploy): adopt the live demo-reset and demo-snapshot scripts, which had been fixed on the box and never committed back. check-config-drift flagged both. The live copies are newer and larger - reset 7286 bytes from 29 Aug against 5108 from 12 Aug, snapshot 2836 bytes from 1 Sep against 2187 from 24 Aug - and heratio-deploy.sh matches the tracked copy byte for byte and mtime for mtime, which is what makes the comparison trustworthy rather than a guess. No credentials in either: both read DB_PASSWORD from the instance .env at runtime into MYSQL_PWD, which matters because this repo is public. Both changes are incident fixes, and both are the same failure shape - something that could not tell success from failure. SNAPSHOT: the baseline lives on an NFS automount, and while unmounted that path still exists as an ordinary local directory, so mkdir -p created it and the snapshot landed on local disk while the script reported success. Nothing surfaced it, because demo-reset reads the baseline from the real NAS path: it would keep seeing the OLD dump and the OLD version stamp, abort every night on a version mismatch, and the rotation would stop while the snapshot claimed to work. Now refuses to run unless the NAS is actually mounted. RESET: two fixes. Trigger names are unique per SCHEMA rather than per table, so one trigger surviving a half-applied run makes the dump's CREATE TRIGGER fail and takes the entire restore with it - that is ERROR 1359 Trigger already exists on ahg_audit_log_no_update_chained, 28 Aug 2026. A pre-restore sweep drops them first, and it distinguishes no triggers from the sweep could not run, because a sweep that fails quietly and calls itself skipped is exactly how the restore meets the error it exists to prevent. Second, a failed restore is now fatal. It used to log restore FAILED and carry straight on through the truncate, the article re-apply, the onboard and the help re-ingest, then print === demo reset done ===. A run that reports success it did not achieve is worse than one that stops: it leaves a half-applied database looking like a finished reset, and the next demo-snapshot would freeze that state as the demo's permanent baseline. Both scripts pass bash -n. No application code changed.
