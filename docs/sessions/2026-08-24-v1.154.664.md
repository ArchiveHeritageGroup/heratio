# v1.154.664 (2026-08-24)

fix(drift): track mysql_full_dump.sh, and teach the manifest to skip comments. The nightly --all-databases dump script lives in /usr/local/bin and was tracked by nothing, so the umask fix in v1.154.663 would have been lost on a host rebuild with nothing to notice - which is the exact failure the drift check exists to prevent. It is not a Heratio script by ownership, but it writes the backups that carry Heratio's data and every other app's on this box, so it belongs in the manifest. Added as deploy/bin/mysql_full_dump.sh, a new directory mirroring the /usr/local/bin destination rather than reusing deploy/sbin, which maps to /usr/local/sbin. Verified by making the live copy diverge, watching the check report DRIFT, and confirming it returns to ok on restore - 17 files compared, no drift. Checked before committing that the script carries no credentials: it authenticates via /root/.my.cnf, which stays on the host. THE MANIFEST HAD THE SAME DEFECT AS .locked-paths. It had no comment support, so a '# note' line was read as a repo path and reported as 'missing in repo' with a non-zero exit. That is the identical bug fixed this morning in the sibling script, where 45 of 74 lock entries silently matched nothing because an inline comment was taken as part of the path. Fixed at the parser rather than by deleting the annotation: a manifest that cannot be annotated gets annotated anyway, and then lies about it. Two config manifests in one repo, both parsing comments as data, is a pattern rather than a coincidence. ALSO FOUND, and not a leak: the script names /home/backupuser/mysql_backups as the fallback used when the NAS is unavailable, a path the permission sweep in v1.154.663 never visited. It is empty, so nothing was exposed, and future dumps land there at 0600 through the new umask. The directory is left at 0755 deliberately - file modes protect the data and the dumps are 0600, while tightening the directory risks breaking the offsite pull for no gain. The NAS mysql/ subdirectory's 32 dumps were already covered by the earlier sweep and are 0600.
