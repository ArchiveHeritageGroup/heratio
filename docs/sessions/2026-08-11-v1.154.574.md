# v1.154.574 (2026-08-11)

fix(test,schema): make the test suite runnable again + ship digital_object_metadata.file_type nullability as a migration. The phpunit suite had been unrunnable on this host, so recent releases shipped without it. Three causes: (1) the heratio_test MySQL USER had never been created (the database existed with 1170 tables, the account did not) - created localhost-scoped with the password already in phpunit.xml, host-level, not a repo change; (2) an anonymous NerService stub in NerAnnotationBridgeIntegrationTest declared extract(string) while NerService::extract had gained ?int $digitalObjectId - one incompatible declaration was fatal and took the ENTIRE Feature suite down, so zero Feature tests ran; (3) DraftRecordVisibilityTest was order-dependent - AclService caches the resolved user in a STATIC that survives across tests in one PHP process, and phpunit.xml runs executionOrder='depends,defects', so the editor case could run before a guest case and leave an admin cached, making the guest gate look like it leaked drafts. Added the AclService::forgetUser() guard TermProtocolGateTest already uses; test-only state, production is unaffected because each request is its own process. NEW MIGRATION 2026_08_11_120000_make_digital_object_metadata_file_type_nullable: the core schema has long declared file_type nullable (its own comment says 'NULL when metadata is written without a file classification, e.g. EXIF-only updates') but databases predating that correction still carry NOT NULL with no default, so EVERY EXIF-only metadata write fails with error 1364 - the table is empty on those instances, the feature has never once succeeded there. Guarded + idempotent: no-op where already nullable (fresh installs from the core schema, e.g. sasa), widening ALTER otherwise; no down() because reverting to NOT NULL would fail on any row written since. Shipped as a migration rather than hand-run SQL specifically because other instances are already in production and must pick this up on deploy. Suite now: Unit 21/21 green; Feature 231 tests down from 9 errors + 1 failure to 1 error + 1 failure (IcipSettingsTest audit middleware, and one more TermProtocolGateTest order-dependency) - both pre-existing and both confirmed present on v1.154.572 by reverting packages/ and re-running, so v1.154.573 caused neither
