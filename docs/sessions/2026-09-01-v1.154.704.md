# v1.154.704 (2026-09-01)

feat(archaeology,core): relationship interchange for the Harris Matrix + curator-chosen primary image. #1483: built the three capabilities that were genuinely still absent - parsePhaserCsv/exportPhaserCsv (the four-column siteCode,sourceID,stratRelationship,targetID format), a relationship-only CSV import with a downloadable template, and the synonym/refusal vocabulary behind them. EXPORT EMITS ONE ROW PER LOGICAL RELATIONSHIP: the table stores both directions, so the 44 stored rows on Blaauwbosch export as 22 - "A above B" and "B below A" are one observation written twice, not two. siteCode is read but never used to CHOOSE the site; rows naming another dig are counted and reported rather than imported, because silently trusting a file own site code is how one excavation stratigraphy ends up written into another. Preview is a REAL run inside a rolled-back transaction, so its counts and warnings are the ones a commit would produce rather than an estimate from a second code path that could disagree. FIXED A CYCLE-GUARD BYPASS while wiring it: the existing LST import wrote straight to archaeology_context_relationship with a hand-rolled inverse map, so an LST file could record a stratigraphic loop that the form itself refuses. Both importers now share one apply path through ArchaeologyService::addRelationship(), which enforces reciprocity, the self-relation check and the loop guard. Verified on real data: 44 stored to 22 exported, re-importing our own export is 0 added / 22 duplicate / 0 warnings, and a deliberately nasty file had its synonym accepted, its contemporary-with refused with the reason, its unknown context and unknown relation named by line, and both loop-closing rows rejected - with the row count unchanged at 48 after preview. #1489: a curator can now choose the primary image and reorder the gallery. Promoting MOVES digital_object.object_id rather than setting a flag beside it, because a great deal of legacy code reads the primary that way and a second notion of primary would drift from the first - the link table stays the extras, never the primary, and the vestigial is_primary column is forced to 0 so it cannot start disagreeing. The swap is symmetric and carries derivatives with their master, since a derivative left holding the old object_id leaks into every WHERE object_id = IO read; the outgoing primary lands in the slot the incoming one vacated so the order does not jump. Reorder ignores ids from other records and keeps any attachment the payload omits, so a stale page cannot drop a row out of the gallery. Arrow buttons are plain form posts that work with no JS; drag-and-drop is an enhancement layered on top. 246 Feature tests pass.
