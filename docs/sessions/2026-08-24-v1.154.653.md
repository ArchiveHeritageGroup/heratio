# v1.154.653 (2026-08-24)

feat(harris-matrix): new ahg-harris-matrix plugin - stratigraphic analysis and interchange ported from AtoM - #1483. A SEPARATE plugin from ahg-archaeology, deliberately. That module is the site, context and finds catalogue; this is the Harris Matrix as an ANALYTICAL object - checking a recorded sequence for contradictions, and moving it in and out of the formats archaeologists actually use. It adds no tables, reads archaeology_site / archaeology_context / archaeology_context_relationship, and every entry point is conditional on ahg-archaeology being present, so the Stratigraphy page keeps working with only the base module installed. The matrix itself (tiers, edges, cycle detection, same_as union-find) is USED from ArchaeologyService rather than reimplemented - two implementations of one graph is how they drift, which this session has now seen four times in the loan-rule lookup alone. CONSISTENCY REPORT, six checks: stratigraphic loops; contexts with no relationships; sequence split into unconnected pieces (treated as UNDIRECTED, because the question is whether the record ties the dig together at all, not which way round any one relationship runs); contexts recorded both as the same unit AND as one above the other, which cannot both be true; elevations against superposition; and phases against superposition. Cycle detection alone only catches the error that makes a matrix impossible to DRAW - these catch the errors that leave a drawable matrix which is WRONG, the class Le Stratifiant checks. Every check is conservative by design and reports only what the record makes unambiguous: the elevation check looks at above only and needs both elevations recorded, and the phase check ignores unphased contexts, because an unphased context is not a contradiction, it is simply not yet interpreted. A report that cried wolf on ordinary excavation messiness would be switched off within a week and then catch nothing at all. The page also lists WHAT WAS CHECKED, because a clean report means nothing unless the reader knows its scope. LST IMPORT - the format BASP Harris, Stratify and ArchEd write, so it is how an existing site archive arrives. Three header lines, then blocks of five: a unit name followed by exactly four relationship lines (above, contemporary_with, equal_to, below), so the parser advances in fives rather than guessing which line it is looking at. A truncated file is REFUSED with a message naming the offending unit and line, not half-imported - a silently half-loaded site archive is worse than a rejected one. contemporary_with is reported and NOT imported: Heratio records same_as, meaning one unit recorded twice, while contemporary with is a chronological claim about two DISTINCT units, and importing one as the other would merge contexts that are not the same context. Import previews before it commits, and names every unit it could not match rather than dropping them quietly. Relationships are written reciprocally, matching the base module's own convention. DOT EXPORT of the reduced matrix - the drawn edges, the same diagram the page shows, because exporting every recorded relationship would give a correct and unreadable graph, which is the thing a Harris Matrix exists to avoid. Interfaces are drawn dashed because they ARE different. HARRIS MATRIX DATA PACKAGE following Thomas Dye's hm table schema: contexts (label, unit-type, position, period, phase, url) and observations (younger, older, url). observations carries NO relation-type column, so the relation types reduce to later-than pairs and the rest is not expressible - that is the FORMAT'S design, not a loss on our side, and the code says so to stop someone fixing it. Reciprocal rows are deduplicated so each observation appears once. DEPOSIT VS INTERFACE typing in Harris's sense: a cut is an interface, the surface left by an act of removal, not a body of material. Matched on the term NAME, not a term id, because a seeded taxonomy term gets whatever id the instance hands out and a baked-in id would be right on exactly one installation. Verified on dev site 2: 6 checks run clean, DOT emits the reduced matrix (1001 to 1002 to 1003), Data Package produces 3 contexts and 2 observations correctly reduced from 4 reciprocal rows. 250 Feature tests pass, including 5 new cases covering LST parsing, refusal of truncated and unit-less files, contemporary_with never becoming same_as, and the deposit/interface split. DEPLOY NOTE: the PSR-4 autoload entry is in composer.json, which is skip-worktree here and excluded by bin/release because it carries dev-only glue (ahg/mva-claims @dev). The provider registration in bootstrap/providers.php is therefore class_exists()-guarded and the plugin is simply ABSENT until the autoload entry is applied per instance. Each instance needs the one line adding to composer.json plus composer dump-autoload; nothing else.
