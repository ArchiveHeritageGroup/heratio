# v1.154.706 (2026-09-01)

docs(archaeology): Harris Matrix user guide with screenshots from the live demo. Covers the whole feature rather than the new parts only - the deposit/interface distinction and the nine relationship types, recording by hand and what the reciprocal write and loop guard do, all four import formats (context CSV, LST, PHASER relationship CSV, site-to-site), all three exports (GraphViz DOT, Harris Matrix Data Package, relationship CSV), and each of the six consistency checks with what it means and what to do about it. Two things the guide states plainly because both look like defects until explained: observations carries no relation-type column because that is the Data Package schema design, and the relationship CSV emits 22 rows for the 44 stored because the table holds both directions of one observation. Also records a real gap found while writing it - the loop guard only checks DIRECTIONAL relationships, so a same_as between two already-superposed contexts can still introduce a contradiction that only the consistency report catches afterwards. 11 figures captured against heratio.org at v1.154.705 by tests/e2e/docs-harris-matrix-screenshots.spec.js, which now scopes its form selectors: a bare button[type=submit] click landed on the page search form and navigated to /glam/browse instead of submitting the upload, and an a[href*="/context/"] selector matched the create link rather than a context. Demo seeded with BLB-TEACH-2026, a teaching site recorded deliberately wrong so the consistency report has something to find - it reports one error and four warnings against zero on the correctly recorded Blaauwbosch site, which is what makes the report documentable at all.
