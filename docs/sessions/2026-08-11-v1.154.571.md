# v1.154.571 (2026-08-11)

feat(heritage): #1460 un-stub the Add Valuation UI + single GRAP valuation write path. New AhgHeritageManage\Services\HeritageValuationService::record() is the one place a revaluation is written: rich heritage_valuation_history row (previous/new/change, method, valuer name+credentials+organisation, report reference, surplus change, notes), the sparse heritage_asset_valuation date-log, the heritage_asset carrying fields (last_valuation_date/amount, current_carrying_amount, revaluation_surplus floored at zero on a deficit, valuation fields preserved when left blank), and the GRAP 103.51 / IPSAS 45.74 OCI-vs-P&L split via OciMovementService::recordRevaluation (gated on ahg_heritage_oci_movement). HeritageAccountingController::addValuation() was a stub returning a blank form with formAction '#'; it now resolves the asset, shows current carrying amount / last valuation / reserve, offers the 8 GRAP 103.42 measurement bases, and lists prior valuations, posting to a new acl:update POST heritage/accounting/{id}/valuation (storeValuation). 'Add valuation' button added to the asset view page. ValuationHeritageBridge now delegates to the same service via class_exists (no hard cross-package dependency, falls back to its inline write), so Spectrum-driven valuations finally post OCI movements and rich history too; skip_if_unchanged keeps the auto-sync PATCH idempotent
