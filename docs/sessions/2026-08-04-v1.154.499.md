# v1.154.499 (2026-08-04)

fix(import,finding-aid): CSV import no longer times out/duplicates/hangs + finding aid writes to a writable path. IMPORT: App\Jobs\ImportJob had no timeout so the 60s worker default force-killed a CSV import mid-run (TimeoutExceededException) leaving the job row stuck 'In progress'; --tries=3 then re-ran it, each retry creating a fresh job row (the duplicates-itself symptom); retry_after=90 < runtime also released the long job for reprocessing. Fix: timeout=1800, tries=1, failOnTimeout=true, a failed() handler that marks the job row ERROR (never hangs), config/queue.php database retry_after 90->1900, and a clearer flash (runs in background - track under Admin->Jobs; do NOT re-submit). FINDING AID: FindingAidJob + FindingAidController + FindingAidActionsController + InformationObjectController wrote to public/downloads which is read-only for the worker/php-fpm under systemd ProtectSystem (Read-only file system); now write to storage/app/public/downloads and serve via the existing /storage symlink (portable, no per-path exception). Verified: finding aid regenerates. Ops: cleared 3 stuck in-progress jobs to ERROR, pruned failed_jobs 257->1 and ahg_error_log 490->1. Deploy: restart queue workers to load the new job code + retry_after.
