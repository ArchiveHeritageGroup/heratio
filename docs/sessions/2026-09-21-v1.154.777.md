# v1.154.777 (2026-09-21)

fix(deploy): demo reset cron-history re-apply never worked (CH-000139) - the restore dropped and re-created the cron 
  tables and a live scheduler tick re-created one in the gap, so the CREATE died on ERROR 1050. The snapshot is now data only (--no-create-info --insert-ignore) and the re-apply truncates and refills in one session, so the tables never disappear. The 
  snapshot is written 0600 and deleted after use (CH-000135). Tested against a scratch database.
