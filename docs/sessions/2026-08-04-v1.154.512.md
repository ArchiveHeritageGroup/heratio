# v1.154.512 (2026-08-04)

feat(#1447): Phase 2 - attached digital objects now flow into exports. Objects attached directly to a description (Phase 1) join the primary in all three export surfaces: IIIF manifest gets one canvas per attached object (IiifCollectionService::loadObjectAndDigitalObjects, empty-check moved after the merge so attach-only records still get a manifest); EAD gets them in the <daoset> (Ead4Serializer); RiC gets them as rico:Instantiation entries (RicSerializationService::getInstantiationsForRecord). New shared AttachedDigitalObjectService::attachedMasters(ioId) returns the ordered attached masters; each exporter concats it, guarded by class_exists. BUGFIX in attach(): DigitalObjectService::upload stamps object_id on the DERIVATIVES too, so attach() now nulls object_id on the master AND its derivatives - otherwise the reference/thumbnail leaked into WHERE object_id=IO reads (list thumbnail + exports double-counted). Verified: IIIF/EAD/RiC each +2 for 2 attachments; legacy getForObject all set UNCHANGED (no derivative leak); attach-only records still manifest. Phase 3=DAM/museum/gallery/library remain
