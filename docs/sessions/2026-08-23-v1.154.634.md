# v1.154.634 (2026-08-23)

feat(library): give circulation a branch axis - #1473 Phase 1, and fix the loan-rules screen that contradicted it - #1477. Circulation had no concept of a branch: library_loan_rule carried material_type and patron_type under a unique key over exactly those two columns, so an installation could hold ONE rule per (material, patron) pair for the entire system and could not say a title lends 14 days centrally and 7 at a branch. The two branch columns that existed - library_copy.branch and library_hold.pickup_branch - were inert free text: nothing wrote them, no screen offered an input, and across all of packages/ahg-library/src there was exactly one reference to either. A branch is now a repository row, per the SLIMS/Brocade evaluation's foundational decision, reusing the tenancy substrate the catalogue already runs on via information_object.repository_id rather than inventing a second notion of where. New migration adds branch_id to library_loan_rule (NOT NULL DEFAULT 0, 0 = all branches) and widens uk_type_patron to uk_branch_type_patron; nullable branch_id on library_copy, library_patron, library_hold and library_checkout. The sentinel is not cosmetic - that column is part of a UNIQUE key and MySQL treats NULLs as distinct, so a nullable column would permit unlimited duplicate system-default rules, the exact ambiguity the original key existed to prevent; it also matches the '*' wildcard idiom the table already used for patron_type. Backfill matches the free-text names to repository authorised names and logs the match rate; the legacy text columns are deliberately NOT dropped, because dropping the only copy of that data in the same migration that adds its replacement would make a partial match unrecoverable. Resolution is exact-branch before all-branches, and within a branch exact patron_type before '*'; branch outranks patron-type specificity, which is a decision and is pinned by a test. The three consumers - resolveLoanDays, resolveMaxRenewals, generateOverdueFine - each carried their own copy of the rule lookup and had already drifted (two filtered is_loanable, one did not); they now share one matchRule(), because three copies is three chances to miss the next axis. NOTE a bug this nearly shipped with: LibraryBranch::available() memoised Schema::hasColumn once per PROCESS, and the library package's harness swaps the default connection to in-memory SQLite built from four named migrations - so a value cached against MySQL was answered for SQLite, and two existing tests failed with plausible wrong numbers rather than an error (14 days because that is defaultLoanDays()'s fallback; a 10.00 fine instead of 4.50 because no rule matched). The tell was both suites passing alone and failing together. The cache is now keyed by connection, which matters beyond tests - any artisan command pointed at another database read the same stale answer. #1477: the loan-rules screen bound $r->loan_days and $r->max_items, neither of which exists (the column is loan_period_days, and there is no per-rule item cap at all), so both fell through to ?? 14 and ?? 5 - which happen to equal the library_default_loan_days and library_patron.max_checkouts defaults, making every rule render as '14 days / 5 max items' and look plausible while contradicting what circulation enforced. On dev rule 1 is 21 days and electronic is 0 days and not loanable; the screen said 14 for both. Max Items is REMOVED not corrected - a per-rule item cap is a missing concept, not a misnamed column, and #1475 covers adding it with enforcement. The desk was about to grow the same defect: checkoutForm previewed a period resolved without a branch while checkout() lent on the branch's rule, so the screen would quote one due date and the transaction write another; the preview now resolves against the same branch, shows it, and carries it through the POST. CI builds its test DB from database/core/0*.sql and never runs package migrations, so the DDL is mirrored into a new database/core/04_library_branch.sql - same 0*.sql glob bin/install and all five CI workflows use, every statement guarded by a prepared statement because MySQL 8 has no ADD COLUMN IF NOT EXISTS, verified loading twice against heratio_test. Migration applies, rolls back and re-applies cleanly on dev (rollback restored all 11 rules and uk_type_patron). Verified live: branch 630/student 3 days, branch 630/public 21, branch 982/student 21, no branch 21. Released as .634 after a concurrent .633 collision; rebased onto that commit and re-verified. 436 tests pass (238 Feature + 198 ahg-library, 30 skipped).
