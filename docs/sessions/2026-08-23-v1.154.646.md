# v1.154.646 (2026-08-23)

fix(privacy): the POPIA compliance score was invisible - white text on a gradient that never painted. dashboard.blade.php renders {{ $stats['compliance_score'] ?? 0 }}% in a display-1 with text-white, on a card whose ONLY background was an inline linear-gradient. Where that gradient does not paint the card falls back to white, so the score rendered white on white and the card read as blank - which looks exactly like a broken chart or an unimplemented feature. It was neither: PrivacyController computes the score correctly (100, less 10 per overdue DSAR capped at 40, less 15 per critical breach capped at 45, less 5 per ROPA needing a DPIA capped at 20, less 20 with no active jurisdiction) and had been doing so all along. On dev it is 60% - ten overdue data subject requests, visible in the card immediately below it. Fixed by giving the card a solid background-color floor beneath the gradient. White text must never depend on a gradient rendering; a colour floor costs nothing and means the number is always readable. This is an accessibility defect rather than a cosmetic one - the single most prominent figure on the privacy dashboard was unreadable for every user, and no test would have caught it because nothing was miscomputed and nothing errored. Same failure mode as the #1478 family - a real value made to look like an absent one - expressed in CSS rather than PHP. Found while preparing conference screenshots, where the blank card was initially mistaken for a JS chart that had not finished painting.
