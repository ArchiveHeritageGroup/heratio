# v1.154.525 (2026-08-07)

fix(install): bin/install no longer WIPES an existing database on re-run (data-loss guard). Root cause of a client 'the update cleared the database': database/core/00_core_schema.sql starts every table with DROP TABLE IF EXISTS, and bin/install Stage 6 loaded it UNCONDITIONALLY - so running bin/install to apply an UPDATE dropped + recreated every table empty, destroying all content. Added a hard guard: Stage 6 now checks whether the core schema already exists (information_object present) and, unless --fresh is passed, SKIPS the core-schema load with a clear message that this is an update (schema changes come from migrations at Stage 9b, which are additive). Only a genuinely fresh/empty DB - or an explicit --fresh (which already prints ALL prior data wiped) - loads the destructive core schema. Stage 7 (plugin schema) was already safe (sentinel-guarded, DROP-free CREATE IF NOT EXISTS); seeds are additive. Verified: bash -n clean; guard skips when information_object exists. UPDATES = git checkout tag + php artisan migrate --force, NEVER bin/install.
