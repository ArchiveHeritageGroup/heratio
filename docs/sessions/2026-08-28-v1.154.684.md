# v1.154.684 (2026-08-28)

feat(museum): build the provenance display - the page was a stub that could never show anything. MuseumController::provenance() was '$provenanceChain = collect();', a hardcoded empty collection, so /museum/{slug}/provenance rendered 'No provenance data.' for every object forever - while provenance_entry held real chains keyed on those very objects (53 rows on dev, one with 7). That is the #1478 defect class: a view bound to something the controller never produces, failing silently into an empty state rather than an error. A museum record IS an information object, so the data was always reachable. Now reads through ahg-io-manage's ProvenanceService - which already owns chain, overview, documents and timeline - rather than a second implementation of the same lookup; resolution is class_exists-guarded since ahg-museum declares no dependency on that package. Gated with the same ACL read check the information-object provenance page uses: provenance carries acquisition prices, Nazi-era findings and cultural property status, so it must not be looser than the record it describes. The display renders a curator summary, acquisition and custody facts, due diligence, and the ownership chain with sale prices, auction houses, evidence and sources. A GAP IS A FIRST-CLASS STATE, not a missing row - an honest provenance says ownership here is unknown rather than quietly closing the chain over it. Two judgements the tests pin: 'none' is the cultural-property vocabulary's no-concern DEFAULT, not a finding, so it no longer raises a due-diligence card that would imply a determination the curator never made - caught because my first version rendered one for an object with no concerns at all; and amber is reserved for an OPEN question, since colouring a cleared or restituted record as a caution misreads the finding. Verified against the real Vermeer chain on dev: 7 entries, 7 certainty badges, the gap entry rendered as a gap. 244 Feature tests pass, including 6 new ones.
