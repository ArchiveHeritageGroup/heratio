# v1.154.629 (2026-08-21)

fix(ai): health checks were consuming 91.6% of the AI gateway quota, then exhausted it and blocked every AI path. The gateway key hit 50,000/50,000 at 2026-08-20 20:23 SAST and began answering 403 {detail: No requests remaining} to EVERYTHING - NER, embeddings, HTR, chatbot, translate - for 11 hours. Cause: LlmService's ollama health probe called the AUTHENTICATED /ollama/api/tags on every check plus /ollama/api/version on success, and both ahg:llm-health and ahg:services-check run every 5 minutes on every instance. Two live instances therefore spent ~3,100 gateway requests A DAY asking whether the gateway was awake: 21,929 of 23,936 calls over the last 7 days (91.6%), and 24,005 of the key's 50,000 lifetime requests. Liveness now uses {base}/health, which needs no key and consumes no quota; the model list and version still come from the authenticated passthrough but are cached for an hour, since a model list does not change between two five-minute ticks. Measured: 3 consecutive health runs now generate ZERO gateway requests (was 6). Second fix - every non-2xx used to collapse into 'Cannot connect to Ollama at <url>', so a 403 quota refusal was reported as a connectivity fault and this morning's triage went looking for a network outage while the gateway answered 200 on /health. New describeHttpFailure() surfaces the status code, the gateway's own detail, and an actionable hint; the check now reads 'Gateway reachable but the model list was refused: HTTP 403: No requests remaining (API KEY QUOTA EXHAUSTED - top up the key on the gateway; every AI path is refused until then)'. Verified against the live exhausted gateway. 231 Feature tests pass
