# v1.154.573 (2026-08-11)

fix(core): one shared 'finish creating a record' step - publication status + closure node (#1461, #1462). Creating an information object is not just the information_object row: it also needs a status row and a hierarchy-closure node. ~17 paths hand-rolled their own creation and most omitted one or both - 11 files wrote no status at all (record has neither Draft nor Published, so it 404s for guests AND is matched by no publication-status filter - a state no operator chose), and 15 paths skipped the closure tree (record absent from every closure-backed descendant query, including from its own ancestors, so a collection walk silently skips it; lft/rgt is chronically stale which is why closure is authoritative). New AhgCore\Services\RecordCreationService::finalizeInformationObject() / ensurePublicationStatus() / ensureClosureNode(), both halves idempotent - an existing status is never overwritten and addNode was already idempotent + self-gating. Placed in ahg-core, not ahg-information-object-manage, so importers and sector packages depend only on core (same direction ClosureMaintenanceService already runs); InformationObjectService's three methods are now thin delegates so existing callers are unchanged and the logic lives in one place. Wired into all remaining paths: api V1/V2, dam, library, museum, records-manage email capture, ric (RicEntityService + RdfImportService), metadata-export EAD/MARC importers, core EadImport + LoadDigitalObjects commands, exhibition LostPlace commands, io-manage DigitalObjectController + the add-child path. Everything defaults to Draft, which preserves current effective visibility exactly (a missing status row already reads as unpublished) - nothing becomes newly public. SeedScaleCorpusCommand deliberately keeps its bulk --build-closure rebuild instead of per-row writes, and now warns when the flag is omitted rather than leaving the corpus silently absent from descendant queries. Verified live against the create form (Draft default / explicit Published / out-of-range -> Draft), DamService, LibraryService, MuseumService and InformationObjectService, plus double-call idempotency; coverage re-scan reports no gaps across all 23 creation sites
