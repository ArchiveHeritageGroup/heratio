# v1.154.608 (2026-08-14)

fix(nas-watchdog): self-gate on local storage, and stop passing a string as related_id. Two bugs in ahg:nas-watchdog. First, the probe requires config('heratio.storage_path') to be a mountpoint with a readable archive/ subdirectory, so an install whose storage is deliberately LOCAL - here HERATIO_STORAGE_PATH=/usr/share/nginx/sasa/uploads - failed two of three checks every 5-minute tick and raised 'Storage NAS is DOWN' about a NAS it does not use. The command now self-gates on heratio.nas_watchdog_enabled (NAS_WATCHDOG_ENABLED, default TRUE so NAS-backed installs are unaffected), returning before it probes or notifies, matching the self-gating pattern of ahg:encryption-bulk-apply. The NAS at 192.168.0.111:/mnt/tank/heratio was mounted and healthy throughout - this was a configuration mismatch, not an outage. Second, the notification passed relatedId: $state - the string 'down' - into ahg_notification.related_id, which is bigint unsigned, so every alarm threw SQLSTATE[HY000] 1366 and the in-app bell row was NEVER written on any install since the command was added; only the workbench drop-file landed. Now relatedId: null, since a mount check has no numeric entity and relatedType 'nas' already carries the meaning. Verified: the forced alarm now inserts the bell row cleanly (first one ever), and the disabled path logs a no-op and exits
