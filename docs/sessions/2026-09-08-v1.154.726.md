# v1.154.726 (2026-09-08)

fix(ai-services): HTR can no longer be dragged off the gateway onto a GPU node by a stale env var. heratio.org logged 'HTR health check failed: cURL error 7: Failed to connect to 192.168.0.115 port 5006' twice a day. .115 is the standby-only node with the broken driver, nothing is listening on 5006, and a GPU node port is exactly what the gateway rule forbids an application to open a socket to. THE FIX WAS ALREADY MADE, AND WAS BEING BYPASSED. heratio#131 moved HTR onto the gateway and left a comment saying HTR_SERVICE_URL was a developer-only override, no longer the production source of truth. Nothing enforced that. Both heratio and heratio-dev still carried HTR_SERVICE_URL=http://192.168.0.115:5006 in .env, an untracked per-instance file, so on every instance that mattered the override WAS the production source of truth, months after the fix. DonutService had already met this and solved it - #1368 ignores a raw-node DONUT_SERVICE_URL - and HtrService never got the same guard, which is why its stale line still bit and Donut's did not. HtrService now refuses a raw-node override the same way, so the .env lines are inert on every box without anyone editing them. That is deliberate: a protection needing per-instance reapplication is one that eventually is not applied, which is precisely how a fix from #131 was still being bypassed. The guard is a public static so it is directly testable, matching how the other decisions in this codebase are pinned; 12 tests cover the stale value, the HEALTHY node (still a node, still refused), ollama by port alone, localhost, all three RFC1918 ranges, and the 172.16-172.31 boundaries, because an over-broad match would refuse legitimate public hosts. The view was worse than the service and is also fixed: htr/sources.blade.php read HTR_SERVICE_URL directly with a hardcoded http://192.168.0.115:5006 fallback, bypassing both the gateway and the service's guard. It now asks HtrService::baseUrl(), which is the single source of truth for where HTR lives. WHAT THIS DOES NOT DO IS MAKE HTR WORK. Nothing is listening on 5006 on any host, and the gateway's own legacy proxy answers 502 'legacy HTR upstream unreachable' for 127.0.0.1:5006 - the service is not deployed anywhere, and the gateway does not list it among ner, summarizer and translator. The health check now fails in 0.13s instead of a 3-second TCP timeout, logs nothing because a 502 is a response rather than an exception, and reports unhealthy accurately. The remaining error is the correct one: HTR is down. 1126 Package tests pass, up from 1114, and 286 Feature tests pass.
