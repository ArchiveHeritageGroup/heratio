# v1.154.713 (2026-09-04)

fix(privacy,spectrum): the jurisdiction registry is now the only list of jurisdictions, and the seeded flags render. FOUR COPIES, NOT ONE: the privacy dashboard and the Spectrum compliance page each hardcoded six regimes in their menus, the complaint form four, and SpectrumController carried a seventh as a PHP array, while PrivacyController kept a second copy of the registry query. So a regime switched off in the registry stayed on offer everywhere, one added to it appeared nowhere, and the seed could drift out of step with the product for months without anyone seeing it. All of them now read PrivacyService::activeJurisdictions(), one reader, with activeJurisdictionsByRegion() supplying the menu headings so the registry decides those and their order too. The complaint form was not passed jurisdictions at all and now is. THE SEEDED FLAGS NEVER WORKED: install.sql stored emoji in icon, but every view builds a flag-icons class from it, so a fresh install rendered the dead class fi fi- followed by an emoji and showed no flag. Dev held ISO codes and looked correct, which is the same reason the missing rows survived. Four sources agree on ISO - dev's data, the 'un' fallback, SpectrumController's array and the hardcoded views - and only install.sql disagreed. Converted, and asserted by test, because the two rows added yesterday repeated the mistake. SPECTRUM SHOWED AFRICA ONLY: the All Jurisdictions view intersected against popia, ndpa and kenya_dpa, on a page whose own menu offers Canada and California, in a product that must not be framed regionally. It shows every active jurisdiction now. The regression test changed shape because these edits made its old assertion vacuous, which its own guard caught and reported: with the menus now generated, it instead asserts that no blade names three or more jurisdictions directly. Three rather than one, because gating a single regime is legitimate - the PAIA button is South African and correctly tests for popia. Proven by reintroducing a hardcoded menu and watching it fail. Verified past the suites: every blade compiles, both routes resolve and redirect to login rather than error, and both views read only keys the shared reader returns. 391 Package tests pass, up from 390, and 286 Feature tests pass.
