# v1.154.601 (2026-08-14)

fix(cron): three scheduled commands that had been failing on every run. (1) ahg:webhook-retry carried its own copy of the retry query referencing three columns ahg_webhook_delivery does not have - attempts, last_response, last_error, versus the real attempt_count, response_code, response_body - so it had failed with 'Unknown column d.attempts' on every run since v1.82.1 on 2026-05-25 and had never once worked. It now delegates to AhgApi WebhookService::processRetries(), the implementation the rest of the webhook stack already uses, which also brings the #1395 SSRF guard on the delivery URL and disabled redirects that the local copy lacked; processRetries gains limit/maxAttempts parameters plus the is_active filter the command had, so nothing is lost. (2) ahg:services-check probed the AI gateway at Ollama's native /api/tags, which the gateway does not expose and 404s, reporting a healthy gateway as DOWN and exiting 1; the probe now uses /health for a gateway URL and keeps /api/tags for a native Ollama host. (3) ai_condition_service_url was SEEDED as http://localhost:8100 by ahg-condition install.sql, but no such service ships with Heratio, so every instance probed a URL pointing at nothing and failed the check for ever; seeded empty now and a migration clears the exact stale default, leaving any operator-set value alone. Also ahg:federation-harvest --all-active harvested the atom_local pseudo-peer, which is this instance's own index with a placeholder base_url of '-', timing out after 30s and exiting 1; --all-active now skips atom_local and peers without a usable base_url, while an explicitly named --peer is still harvested as asked
