# v1.154.586 (2026-08-12)

chore(deploy): #1465 version the host-level operational scripts under deploy/sbin. heratio-deploy.sh, heratio-demo-snapshot.sh and heratio-demo-reset.sh existed only at /usr/local/sbin on one box, unversioned and undeployable, while carrying logic that took real incidents to arrive at - a rebuilt host would have lost the lot and rediscovered the failures from scratch. Now mirrored in the repo byte-for-byte (verified with diff), along with deploy/cron/heratio-demo-reset which schedules the 02:00 job. Checked for secrets first: none of them hardcode credentials, all read DB_PASSWORD from the instance .env at runtime. deploy/sbin/README.md documents install commands, which scripts are demo-only, and the TWO CONTRACTS that are non-obvious and must not be tidied away: (1) the baseline carries a version stamp and the reset refuses to restore when it does not match the deployed version.json - the baseline is a FULL dump so restoring an old one rolls the SCHEMA back, which is exactly what happened nightly between 2026-07-10 and 2026-08-12; (2) heratio-deploy.sh restores .git and tracked-file ownership after composer/npm/git run as root - the 2026-07-10 root-run git left 399 files in .git root-owned, www-data could no longer update refs/heads/main, HEAD detached, and the script's own 'git checkout main' would have rolled the app back 315 releases, which is why deploys moved to manual pulls, which skipped the baseline rebase, which caused contract 1's failure. One ownership slip, five symptoms - written down so the next person does not remove the chown as redundant. ALSO DOCUMENTED, NOT SILENTLY CHANGED: heratio-deploy.sh health-checks https://heratio.theahg.co.za/ but /usr/share/nginx/heratio/public is served by heratio.org.conf (server_name heratio.org www.heratio.org), so that URL returns 301 and the check reports a redirect rather than confirming the app is up. It only echoes the code and never fails the deploy, hence going unnoticed. Left as-is so the repo copy mirrors the running one exactly; both should be fixed together. README also carries a diff loop for spotting drift until the automated check in #1465 exists
