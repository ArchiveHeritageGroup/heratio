# v1.154.709 (2026-09-02)

fix(ai,research,ric): clear the dev error log by fixing what put entries in it, and finish #1480. ERROR LOG: two of the six logged URLs still reproduced; the other four had been fixed since. ResearchControllerHelpers read $this->service, which 37 of the 39 controllers using the trait declare and two do not - ResearchCustodyController ($custody) and ResearchQuotaController ($quota) - so both threw Undefined property the moment they rendered a sidebar, which is every page they serve. The trait now resolves the service without depending on a property name, using isset() rather than property_exists() because an unassigned typed property passes the latter and then fatals on read. RIC LOGS threw Illegal operator and value combination on an ordinary unfiltered search: ConvertEmptyStringsToNull rewrites an empty query parameter to NULL, input() default only applies when the key is ABSENT, so a present-but-empty filter arrived as null, passed the !== empty-string guard and reached whereDate(created_at,>=,null). Cast at the point of read; a scan found the same shape at 8 sites across ahg-ric and ahg-discovery, where the 2-arg form is quieter but worse - where(entity_type, null) becomes IS NULL, so submitting the filter form empty returned nothing instead of everything. #1479 was already fixed in v1.154.647 and is verified closed by data: 0 orphans across all 2,124 entities. #1480 code half shipped there too; what remained was 2,003 rows asserting confidence 1.0000 that NO detector produces - spaCy emits no per-entity score and PiiScanService ceiling is 0.95, and the pii_detector rows at 1.0 carry NER entity types, so they came from the same fabricating path. A migration nulls exactly 1.0000 and leaves the 79 genuine scores alone. THE MIGRATION ALONE WOULD HAVE CAUSED SILENT LOSS: ahg:ai-sync-entity-cache filters confidence >= 0.70, which is false for NULL, so entity-cache coverage would have collapsed from 22 objects to 1 - and that regression was already latent, since the honest NULLs from v1.154.647 are invisible to the same filter. An unscored entity is not a low-confidence entity, so unscored entities are now included by default with --require-score for scored-only. Verified end to end on dev: 2,003 cleared, 79 kept, coverage held at 22 objects / 1,380 entities, --require-score narrows to 1. 256 Feature tests pass.
