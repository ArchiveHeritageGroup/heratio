# v1.154.442 (2026-07-28)

v1.154.442: feat(archivematica): complete the Heratio->AM->Heratio round-trip (auto-processing config, identifier metadata, real-DIP parsing).

Tested against the live Archivematica VM (192.168.0.150; SS :8001, dashboard :62080). Four changes close the loop so a record's images go to AM for preservation and the DIP comes back onto the same record, unattended:

1. TransferService::stageFiles now drops a processingMCP.xml (new resources/processingMCP.xml) into every transfer - the AHG 'Store DIP' config plus the auto 'Approve normalization' choice - so AM runs the ENTIRE pipeline without a human (previously it stalled at 'Approve normalization') AND stores the DIP in the Storage Service (not only uploads to AtoM), which is what Heratio's pull ingest needs. An operator override at <staging>/processingMCP.xml wins.
2. stageFiles also writes metadata/metadata.csv carrying the record's dc.identifier (+title), so AM preserves it into the DIP METS and DipMatcher can link the returning DIP back to its source information_object (identifier strategy).
3. MetsParser::extractAccessFiles now reads fileGrp USE='original' as well as 'access' - a real AM DIP's objects/ files are labelled 'original', so the parser previously found zero.
4. DipIngestService::resolveAccessFilePath now matches AM's on-disk '<file-uuid>-<originalName>' naming (the METS href carries the clean name), so the files actually resolve.

Verified end to end: transfer 7 images -> AM normalizes/AIP/DIP unattended -> DIP stored -> pulled + matched by identifier -> 7 access files ingested as digital objects on the source record.

(VM-side note, not shipped: the AM MCPClient was failing every job on a stale /tmp prometheus-multiproc dir; restarting archivematica-mcp-client cleared it.)
