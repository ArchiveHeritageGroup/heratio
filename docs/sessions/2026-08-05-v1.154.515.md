# v1.154.515 (2026-08-05)

feat(#1446): per-site php-fpm pools for prod + saturation monitor (SPOF hardening). The single shared www pool was a cross-site SPOF (2026-08-04: a CPU-heavy co-tenant job jammed all 100 workers, every site 502'd for hours). Added dedicated php-fpm pools for the two production sites - heratio (/run/php-fpm.heratio.sock, 25 children) + sasa (/run/php-fpm.sasa.sock, 15) - additively (own sockets, mirror www.conf directives, /fpm-status enabled); repointed heratio.org + sasaarchive vhosts fastcgi_pass to them, so a co-tenant jamming www can no longer starve production. Applied host-side with php-fpm -t + nginx -t gates + graceful reloads; verified heratio.org 200 / sasa 302 / shared-pool co-tenant 200, each prod site served by its own pool. bin/fpm-pool-monitor (cron, www-data, read-only) reads each pool /fpm-status via cgi-fcgi and drops a Workbench alert on saturation (active>=85pct max_children, listen queue>0, or ceiling-hits climb), debounced 900s. Ops runbook + rollback + reference pool.d configs in docs/ops/fpm-pool-isolation.md. All reversible per-site in under 1min.
