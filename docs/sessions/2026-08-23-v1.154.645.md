# v1.154.645 (2026-08-23)

fix(exhibition,marketplace,ipsas,repository,research,settings,semantic-search): screens reporting 0 while the data said otherwise - #1478 numeric findings. Twelve findings whose fallback rendered a FIGURE rather than a blank, which is the dangerous end of this defect class: a count or an amount reads as fact, so 0 is taken as 'none' rather than 'not wired'. THE BIGGEST FIND WAS NOT A BINDING BUG AT ALL. Chasing stop_count led into ExhibitionService::get(), which ordered five queries by sort_order and one by category - and NO exhibition_* table has either column; they use sequence_order and checklist_type. ORDER BY on a non-existent column is a hard SQL error, so that method threw SQLSTATE[42S22] for EVERY exhibition and the exhibition detail view was down entirely. It now loads with real data (objects, storylines, sections, events, checklists). A page that 500d on every record had been sitting behind a display-binding finding. NOTE the first cut of that fix bulk-replaced sort_order across the whole package and caught ReconstructionService's OWN CREATE TABLE sort_order plus a provider's menu ordering, both correct as they were; reverted and redone against only the five exhibition-table queries. MARKETPLACE REVENUE REPORT showed 0 for every figure: getRevenueStats() returns an ARRAY and admin-reports.blade.php read it as an OBJECT on all four lines, and two of the four keys were wrong as well (net_seller_payouts / transaction_count against the service's total_seller_amount / total_sales). The underlying data held R37,000 revenue, R3,700 commission, R33,300 seller payouts and 2 sales. IPSAS INSURANCE had FIVE bindings and not one matched a column - provider_name, coverage_type, coverage_currency, coverage_amount, premium_amount against insurer, policy_type, currency, sum_insured, premium; a sixth, premium_currency, has no separate column so the premium is quoted in the policy currency. REPOSITORY DISK USAGE was never computed anywhere: the upload-limit screen reads disk_usage off the repository row and repository has only upload_limit, so the page reported 0 GB used - which is the one number an operator is on that page to check. New RepositoryService::diskUsageBytes() sums digital_object.byte_size per repository, summed on demand rather than denormalised because a stored counter drifts on every delete; repository 731 actually holds 0.11 GB. COUNTS NEVER COMPUTED, now correlated subqueries so a row with no children still appears and is not duplicated per child: thesaurus synonym_count (a term with 4 synonyms displayed 0), storyline stop_count (verified 2/4/0/0/2 against the table), webhook delivery_count, research collection items_count, marketplace follower_count and listing_count. MARKETPLACE AUCTION prices joined from marketplace_auction - starting_bid / reserve_price / buy_now_price aliased to the auction_ prefixed names the listing screens read. TWO COULD NOT BE FIXED and are on #1481: heritage analyticsSearch() is a one-line stub returning empty arrays and never passes popularQueries, and ahg-core's add-digital-object.blade.php is an orphan duplicate nothing renders. Baseline 89 -> 71; the remainder is the low-severity tail of blank and label fallbacks. 242 Feature tests pass.
