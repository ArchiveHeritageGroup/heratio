# v1.154.690 (2026-08-29)

ci: run migrations so the test database matches a deployed instance - #1471. Both workflows built heratio_test from database/core/0*.sql plus database/seeds/0[0-6]_*.sql and never ran artisan migrate, so CI tested a schema no instance actually runs. Reproduced rather than taken on trust: a database built exactly the way CI builds one has 1124 tables against dev's 1266, and status.id is still auto_increment with the object FK absent, so the id-less INSERT that #1470 hardened against is accepted - CI would stay green on a write every real instance rejects. Migrations now run after the seeds in all six database-setup blocks, five in test.yml and one in e2e-tests.yml, because the backfill migrations rehome seeded rows. Root credentials, since the schema above is loaded as root, and --env=testing for APP_KEY. Verified end to end against a scratch CI-shaped database: every migration completes, a second run is a clean no-op, table drift falls from 142 missing to 17, and status.id ends up correct - the forbidden insert is then rejected with 'Field id doesn't have a default value'. The 17 remaining are 7 tables created lazily at runtime by their own services and 10 belonging to a package that is not migration-managed, so their absence is by design. The full Feature suite passes against the migrated schema: 250 passed, 26 skipped, no failures - four MORE tests run than against the unmigrated database, so this widens real coverage rather than just changing its shape.
