# v1.154.575 (2026-08-11)

fix(test,icip): green test suite + split the two logs that both claimed icip_access_log. TEST SUITE: the last two failures are fixed and Feature is fully green (231 tests, 0 errors, 0 failures, 30 skipped, stable across repeated runs; Unit 21/21). Both were the same class of fault as the DraftRecordVisibility one - statics that are correct under PHP-FPM (where each request is its own process) but leak between tests, because phpunit runs one process and phpunit.xml sets executionOrder='depends,defects' so a polluting case can be reordered ahead of the case it breaks. TermProtocolGate::$restricting memoises 'does anything restrict?' per request; an earlier case that ran before any protocol existed left 'nothing restricts' cached and the later gate then filtered nothing, so a restricted record looked visible to a guest. Added TermProtocolGate::forgetMemo() (also clears $protocolTable) and called it in TermProtocolGateTest::setUp, mirroring AclService::forgetUser. Production behaviour is unchanged - the memo is deliberately per-request and must stay that way so an editor's protocol takes effect on the next page load. ICIP LOG COLLISION (real bug, not just a test fault): two features both created a table named icip_access_log with incompatible shapes - the route audit (AuditIcipAccess middleware + ahg-icip install.sql: user_id/ip_address/path) and #1427's graded-access decision trail (LogsIcipAccess + the provider boot self-heal: information_object_id/decision/restriction_types/reason). Both used CREATE TABLE IF NOT EXISTS, so whichever ran first won and the loser's INSERT died on an unknown column inside a try/catch that logs and continues. The self-heal runs every boot and wins, so the ROUTE audit has never recorded a single row and the admin setting 'Log all ICIP record access' has been inert since it shipped. On a fresh install where install.sql lands first the failure inverts and #1427's accountability trail is the one that silently breaks - worse, since that is the CARE 'authority to control' record a source community would ask us to account for. Split: route hits now go to a new icip_route_access_log (migration 2026_08_11_140000, guarded + idempotent, and defensively moves rows + rebuilds the graded-access table on an install where the route shape won); the middleware writes there; the provider self-heals the new table alongside the existing one so it exists without depending on install order or on migrations having run; install.sql now defines BOTH tables correctly instead of only the colliding one. icip_access_log keeps its name for #1427 because that is the log that matters most and route hits should not dilute it
