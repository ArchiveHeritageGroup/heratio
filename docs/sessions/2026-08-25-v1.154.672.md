# v1.154.672 (2026-08-25)

fix(archaeology): transitive reduction on the Harris Matrix - #1482. ArchaeologyService::harrisMatrix() drew every above/cuts/fills row as an arrow and removed nothing another path already implied. Strictly that is not a Harris Matrix: removing implied relationships is one of Harris's rules and the reason the diagram is useful at all. On a site with a few hundred contexts the redundant edges multiply and the drawing degrades into the unreadable web the matrix was invented to avoid, and because the Mermaid source is built from the same edge set, the defect travelled into anything generated from it. Verified fixed there too - the export now carries two arrows for the issue's three-context case. REDUNDANCY IS NOT BAD DATA, which is why this had to be a drawing fix rather than an import validation. A recorder who observes that 1001 overlies 1002, 1002 overlies 1003 AND 1001 overlies 1003 has recorded three true, directly observed statements; the third simply carries no information the diagram does not already express. The CSV import should keep loading all three. GUARDED ON ACYCLICITY, and the guard is the point rather than defensive habit: transitive reduction is only defined on a DAG, and a contradictory sequence must be shown AS RECORDED so the archaeologist can see the contradiction. Tidying a graph you have just declared impossible would hide the very thing the reader needs. Verified: with a cycle present the reduction is skipped, the edges stand as recorded and tiers stay empty. Runs after the same_as union-find, because merging two contexts into one node can create redundancy that did not exist between them. EXTRACTED TO A TESTABLE METHOD rather than left inline. The archaeology tables are created by migration and the CI test database is built from database/core/*.sql alone (#1471), so a database-backed test of this would skip in CI and prove nothing. reduceTransitively() is pure graph logic and now has six tests that actually run - including the case a careless implementation breaks, two contexts independently over a third, which is ordinary matrix shape and not redundancy at all, and a diamond-plus-shortcut that fails if reachability is tested against an edge set being mutated mid-loop instead of the full one. THE TWO ADJACENT OBSERVATIONS ON THE ISSUE ARE ALSO ADDRESSED, since a fixer was in this code anyway. The edge key collapses a node pair to one arrow, and which relationship type won used to be decided by read order; it is now deliberate - the more specific label wins, because cuts and fills describe HOW one context is later than another while above says only THAT it is. And a cycle now reports WHICH contexts are involved: the nodes still carrying in-degree when the queue drains are exactly the ones caught, they were already to hand, and 'there is a cycle somewhere among your 200 contexts' is not something anyone can act on. The count of removed edges is returned as redundant_removed rather than the reduction happening silently - that an excavation record contained implied relationships is a fact about the record, not an internal detail of the drawing. 231 Feature tests pass. The parity twin on ahgArchaeologyPlugin is untouched and still carries the original logic.
