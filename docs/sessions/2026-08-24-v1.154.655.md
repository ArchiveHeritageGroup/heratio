# v1.154.655 (2026-08-24)

fix(acl,research,naz,heritage,jobs,function,security-clearance): #1478 down to 8 - chain of custody built, five pages that were broken outright, and a scanner that stops crying wolf - #1478. Baseline 24 -> 8, and the 8 that remain are both FEATURE clusters the issue always classed as such: six computed_data (the landing-page per-block-type resolver) and two heritage analytics stubs, one of which belongs to #1481. Every rename and wiring finding is cleared. CHAIN OF CUSTODY, BUILT. research_custody_handoff, three views and nothing else - no controller, no service, no route, and not one read or write of the table anywhere in PHP. The model is deliberately two-part: research_material_request holds the CURRENT state of a request, research_custody_handoff is the APPEND-ONLY log of movements. A row is never edited; a correction is another row, because a custody log that can be edited in place is not evidence of anything. New ResearchCustodyService is its one reader and writer, a controller and three routes reach it, and the retrieval queue links to all three screens. expected_return was collected by the checkout form and had nowhere to go - new column, migration plus a mirror into database/core/08_research_custody_columns.sql, because CI builds its test DB from those files and never runs migrations. Five new tests pin the two properties that make it evidence: a movement always writes a row, and the request state and the log never disagree. FIVE PAGES BROKEN OUTRIGHT BEHIND A FINDING. The declassification management page used NONE of the three variables its controller passed and needed two it never received - its body was a copy of the per-object declassification FORM in another package, so both tables read empty on every request whatever the schedule held. The NAZ researcher page THREW for every researcher: its Edit button pointed at ahgnaz.researcher-edit, a route never defined - and behind it researcherUpdate() was complete, with validation, PII encryption and an audit entry, and no form or route could reach it. Registering a NAZ researcher was IMPOSSIBLE: registration_date is validated as required and no field collected it, proven both ways - the old payload is rejected with 'The registration date field is required.' The security-clearance user page showed a clearance with no level name on a default grey badge, because sc.name and sc.color are aliased to classification_* and BOTH alternates in the chain were dead. The NAZ visits table had three of its four columns wrong - what was consulted is materials_provided, the purpose belongs to the PERMIT, and a visit has no status column but its check-in and check-out times say exactly where it got to, so the state is derived rather than invented and never borrows the permit's. ONE IMPLEMENTATION, NOT TWO. The declassification schedule is read by ahg-acl and ahg-security-clearance, which cannot see each other - both depend on ahg-core, so the query lives there now and both delegate. Note there is also an EMPTY security_declassification_schedule table with a near-identical shape and no reader or writer anywhere; object_declassification_schedule is the one the application uses, and the code says so. Heritage timeline periods gained one TimelinePeriodLabel used by all five readers, replacing an inline formula on the landing page that rendered the BCE period as '-5000-499' and a year_label the timeline read and nothing produced - so a timeline listed period NAMES with no dates at all. THE SCANNER LEARNED SOMETHING, AGAIN: it now blanks Blade comments before scanning. A reusable component documents its own usage in a comment block naming properties it never reads, and reporting a defect in a comment is how a tool gets switched off. That removed exactly one finding, the false positive. ALSO: jobs recorded errors in output and the red Error(s) card keyed on a never-written error_output, so a failed job's error showed in a neutral grey Output card; the access-request review screen never selected the requester's current clearance or e-mail; view-room and its four wrong seat bindings now have a route; relation_dates is composed from relation_i18n.date or the structured start/end; and _object-list-csv was deleted as superseded by a working, different ExhibitionService::exportObjectListCsv. STILL OPEN, deliberately: the function show page silently drops five sections (relatedActors, parallelNames, otherNames, languages, scripts) - looped, isset-guarded, never passed, so nothing throws and nothing renders; and the app writes created_at in UTC while MySQL NOW() is SAST, a two-hour offset that makes any 'recent rows' query lie. 225 Feature tests pass.
