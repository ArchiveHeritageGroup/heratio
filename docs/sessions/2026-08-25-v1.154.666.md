# v1.154.666 (2026-08-25)

chore(deps,help): resync vendor to the lock (Laravel 12.62.0 -> 12.63.0) and cut the help screenshots by 62%. VENDOR was seven packages behind composer.lock - laravel/framework, guzzle and its psr7/promises/uri-template, nesbot/carbon, league/flysystem - so the instance had been running 12.62.0 against a lock that said 12.63.0. This is a catch-up to the committed truth, not a version decision: the lock already specified these. Resynced through bin/deploy-check --fix; 225 Feature tests pass on the new framework and all five checks are green. Worth recording that composer install as www-data FAILED first: vendor has mixed ownership (297 www-data, 61 root at depth 2) and could not delete root-owned files. Both the deploy script and deploy-check run composer as root with COMPOSER_ALLOW_SUPERUSER=1, so that sanctioned path was used rather than a new one - but the mixed ownership is the root cause and will bite again. HELP SCREENSHOTS were 1024-1536px wide and rendered at width=500, so every view of the user manual pulled 6.6MB to display five images at half their pixel width. Resized to 1000px (twice the display slot, so still crisp on HiDPI) and stripped of metadata: 6,712K -> 2,596K, 62% saved, with the largest falling from 1,956K to 497K. Verified one by eye before committing rather than trusting the byte count - these are line diagrams rather than dense screenshots, the text is unchanged and sharp, which is also why they compress this well. All five still return 200 and the help page renders. THIS DOES NOT RECLAIM REPO SIZE and is not meant to: the originals entered git history at v1.154.658 and remain there permanently. The win is page weight for every reader and smaller future checkouts. Reclaiming the history would need a rewrite, which is not worth it for 4MB.
