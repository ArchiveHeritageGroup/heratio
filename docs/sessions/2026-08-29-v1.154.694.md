# v1.154.694 (2026-08-29)

fix(archaeology): the site page's finds table showed Context '-' for every find - #1497. The Context column rendered $f->context_reference, a free-text field meant for a reference recorded on paper where no context record exists. Where a find IS linked to a context - the normal case - that field is null, so the column showed a dash and a correctly-made link was invisible. Verified on the demo: all six Blaauwbosch finds carry a context_id resolving to a real context of that site (SF215 to 1001, three to 1002, two to 2001) and every one rendered as '-'. Worse than a blank cell, because it reads as 'the link was never made' and invites a curator to repair data that is already right - and the context is the most important attribute an excavated find has, a find without it being an object with no provenance. ArchaeologyService::objects() joined object type, material, period and the site but never archaeology_context, so the column had nothing to render. It now joins the context and its slug, and the cell prefers the real linked context, rendered as a link through to the context record to match the site and object columns, falling back to the free-text reference only when there is genuinely no linked context. 246 Feature tests pass.
