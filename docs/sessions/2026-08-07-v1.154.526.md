# v1.154.526 (2026-08-07)

feat(backup): headless backup:run command + BackupService - backups that actually work for real content sizes. The web UI backup (BackupController::create) runs mysqldump + tar synchronously INSIDE a web request, so a real uploads/content dir (16 GB on the reporting client) blows the php-fpm request_terminate_timeout (90s) and returns a non-JSON error page ('JSON error'); when only uploads times out but the DB dump succeeded, the response still reported success -> 'shows success but content is not present'. New AhgBackup\Services\BackupService (shared engine: mysqldump + per-component tar + retention; tar rc=1 file-changed-as-we-read-it treated as success for a live dir) and a 'php artisan backup:run [--components=database,uploads,plugins,framework]' command run the same backup with NO request timeout, for cron or manual use. Non-zero exit if any component fails so cron surfaces partials. Verified: backup:run --components=database produced a valid 37 MB .sql.gz in 26s headlessly. Web-UI queueing is a tracked follow-up. Operators: run backups via 'php artisan backup:run' / cron, not the browser, for large content.
