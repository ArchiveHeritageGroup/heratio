# v1.154.492 (2026-08-04)

i18n(#1416/#1419): SA-language UI coverage via offline NLLB-200 - Xitsonga/Setswana/Sesotho (batch 1). The AHG gateway translate endpoint only exposes af/en/bnt and silently falls back to a generic-Bantu model that produces wrong/identical output (#1419), so instead used the on-disk facebook/nllb-200-distilled-600M offline (per-language FLORES codes zul/xho/nso/tso/ssw/sot/tsn_Latn) as a build-time batch, NOT the runtime gateway. This commit lands ts/tn/st: coverage of the 17922 codebase __() keys rises ts 1.4->73.6%, tn 3.5->73.3%, st 3.5->72.9% (~13k UI-label translations each). Only clean UI labels are translated (strings with %1% placeholders, code, hex colours or trailing-period prose are skipped); passthrough + garbage output is guarded out (~13% dropped); high-frequency ambiguous nav terms were already human-translated so NLLB only fills the specialised long tail. All entries are flagged machine-translated in _meta.json (mt_engine=nllb-200-distilled-600M, mt_batch_count) on top of the existing 'native-speaker review required before production' credit. Written byte-identical to the PHP json_encode format (no diff churn); JSON validated. Remaining nso/ss/xh/zu follow in batch 2; Tshivenda (ve) + isiNdebele (nr) are excluded because the distilled 600M model cannot translate them (English passthrough) - they need a larger NLLB or human translation.
