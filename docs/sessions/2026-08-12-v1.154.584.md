# v1.154.584 (2026-08-12)

fix(rights,icip): #1464 finish the consolidation - two missed live paths repointed, a wrong-label bug fixed, six superseded tables dropped. THE CLEANUP WASN'T CLEANUP. A reference sweep before dropping found two paths the earlier releases missed: (1) AhgExtendedRights\ExtendedRightsService has its OWN embargo methods still reading rights_embargo - v1.154.579 repointed EmbargoService but not these; (2) ahg-scan RightsEnforcementService writes TK labels from ingest sidecar tkLabel tags into rights_object_tk_label, which TermProtocolService does not read - so a label applied at ingest governed nothing, the same enforcement gap fixed in v1.154.581 surviving on a different path. Both repointed to embargo and icip_tk_label respectively. WRONG-LABEL BUG IN v1.154.582, caught before it could bite: IcipLabelAssignmentService::resolveTypeId treated a numeric id as an ICIP id if one existed with that number, but the two vocabularies' id spaces OVERLAP (legacy rights_tk_label 1-19, icip_tk_label_type 1-70) - legacy 15 is BC-CB while ICIP 15 is tk_mg, so saving rights from the form would have attached the WRONG cultural label, which in this domain is the worst failure mode available. The service now refuses to guess: applyLegacyIds / applyCodes / applyTypeIds make the vocabulary explicit and translation always goes via the code. Verified no damage - zero icip_tk_label rows were written in the window, every existing row came from the TK migration which translated by code. DROPPED, each with zero live references after the above: rights_embargo, rights_embargo_i18n, extended_rights, extended_rights_i18n, extended_rights_tk_label, rights_object_tk_label. The drop is guarded - it refuses if the successor table is absent, or if the source holds rows while the successor is empty (meaning the data was never carried over on that instance). A foreign key from rights_embargo_log had to be released first; it is NOT repointed at embargo, because the consolidation MERGED rows rather than copying them so an id surviving in embargo is very likely a different embargo - manufacturing that linkage would be worse than losing it. KEPT: rights_embargo_log (the embargo audit trail, not a duplicate) and agreement_rights_vocabulary (25 curated donor-agreement terms nothing reads yet - authored reference data whose fate is a question for a human, not something a cleanup migration should answer by deleting). MISTAKE MADE AND CORRECTED: I first deleted four TK service methods after a faulty caller check reported zero callers; they are in fact called from RightsAdminController and RightsController, and /admin/rights/tk-labels 500'd. Restored and repointed to icip_tk_label with the admin views' column names preserved by aliasing, so the TK admin surface now writes to the table the protocol gate reads. Rights/licence/embargo tables 45 -> 32. Verified: assign/list/remove round-trip through the restored admin methods, all rights admin pages and record pages 200, embargo and rights services intact, Unit 21/21 and Feature 231 green
