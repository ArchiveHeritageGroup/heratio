# v1.154.733 (2026-09-11)

docs(reference): commit the Outlook mail rules that were written on the live instance and left untracked. The file appeared in prod's working tree as an untracked docs/reference entry during the v1.154.732 deploy. It would have been crawled into KM where it sat, but it was not in the repository, so it travelled with no instance and would have tripped the next deploy's clean-tree check exactly as the v1.154.728 session log just did. Read in full before committing rather than scanned, because this repository is PUBLIC and the file was written by someone else: it carries no credentials, keys or tokens, no third-party addresses, no mailbox contents, and refers to Johan's own address only by description. The three matches a credential grep returns are the prose saying it contains none. What it records is worth having tracked. Mail does not live in Heratio at all - it is the workbench API's delegated per-user OAuth against Microsoft Graph - and it names the wrong turn explicitly: packages/ahg-sharepoint in this repository also has a Graph client, but it is SharePoint and Drive federation with no mail scopes, and mistaking it for a mail surface is the obvious error. It also states the two standing rules that are stricter than any general phrasing: Gmail is off-limits including the linked IMAP mailbox, and every send goes to Johan himself and never to a third party, with drafts the only way to address a recipient because a draft cannot be sent by the tool. First release pushed by www-data with its own deploy key, which is how this was always meant to work.
