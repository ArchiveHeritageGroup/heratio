# Session note, 30 September 2026: what v1.157.0 actually carried

v1.157.0 went out with a message and session log that name only heratio#1517. It carried four issues. `bin/release` commits the whole working tree, not just the staged files, so the first of four planned per-issue releases took everything and the other three aborted with "Nothing to release". This note records what else is in it. Issues: heratio#1516 (closed), #1517, #1448, #1514. Follow-ups filed: #1519, #1520, #1521.

## heratio#1516: RiC search, closed - with a correction

v1.157.0 changed two things in `SparqlQueryService`. One was right and one was wrong, and the wrong one was reverted in the next release.

**Wrong: the dataset.** `SparqlQueryService` defaulted to `/openric-model`, and v1.157.0 made it follow `ahg_settings.fuseki_endpoint` (`/ric`) instead, on the theory that it was pointing at the ontology by mistake. It was not. `/openric-model` also holds Heratio's own agents and places as `urn:ahg:ric:*` with `rico:name`, loaded by `ahg:ric:fuseki-load` (heratio#139). Its callers are built on those: the authority-resolution candidate adapters, and KM grounding (`/api/ric/ground`, heratio#1320), whose packs are keyed on `urn:ahg:ric:*`. For as long as v1.157.0 was deployed, both were reading the archival store and returning archive IRIs instead. The default is back to `/openric-model`; the constructor takes an endpoint for anyone who wants `/ric`. The archival store already has its own client (`RelationshipService`, `RicController`).

This also changes what #1516 was. The 172-second search was measured on a `/ric` copy in the QLever benchmark. In production, search ran against the small `/openric-model` and did find the #139 records by `rico:name`.

**Right: the predicates.** The queries only knew `rico:name` and `rico:description`. The RiC extractor (`packages/ahg-ric/tools/ric_extractor_v5.py`) writes other shapes:

| Concept | What the data holds |
| --- | --- |
| Record and record set names | `rico:title` |
| Agent names | `rico:hasAgentName` -> `rico:textualValue` |
| Place names | `rico:hasPlaceName` -> `rico:textualValue` |
| Term and function names | `rico:hasOrHadName` -> `rico:textualValue` |
| Hierarchy | parent `rico:includes` child, one direction only |
| Dates | `rico:isOrWasAssociatedWithDate` -> `beginningDate` / `endDate` / `expressedDate`, usually on the Production that `rico:resultsOrResultedIn` the record |
| Live-sync stub | `rdfs:label` |
| heratio#139 load (`/openric-model`) | `rico:name` |

: Where RiC data keeps names, hierarchy and dates

`search()` and `getByType()` now match all of these, so they work on either dataset. Search finds the page of entities first, then labels that page with a second `VALUES` query. `RIC_TEXT_INDEX=true` switches search to the jena-text Lucene index built for heratio#18, which `/ric` has and `/openric-model` does not: 0.3 s instead of minutes on the 17.9M-triple store.

The authority-resolution adapters keep their `rico:name` branch and gained the extractor's name shapes. Test: `packages/ahg-ric/tests/Unit/SparqlQueryContractTest.php`, with the fixture `tests/fixtures/ric-extractor-sample.ttl`, which is real extractor output. It checks each query's predicates against the fixture, runs the queries against `/ric` with the text index, and checks that the default dataset still finds a #139 agent.

The lesson: before "fixing" an endpoint, read who calls the service and what they expect back. The grounding doc said `urn:ahg:ric:*` in plain words.

## heratio#1519: why the graph is slow anyway

Re-extraction adds new blank nodes without removing the previous run's. `corporatebody/731` carries 31,660 name nodes and `production/902924` carries 2,112 date nodes. The totals follow: 1.7M `rico:Name` and 1.4M `rico:Extent` nodes against 648 records and 43 agents. Any join through a name or date node pays for it. Filed as its own issue; unfixed.

## heratio#1517: provenance off RDF-star, code shipped, migration pending

Each annotated statement is now a plain node, `urn:<tenant>:<module>:statement:<sha1>`, typed `rdf:Statement` with subject, predicate and object, and the provenance hangs on it. The hash covers the graph IRI plus canonical N-Triples, so writer, replay and migration mint the same IRI and re-runs are no-ops. Shared helper: `packages/ahg-core/src/Support/ReifiedStatement.php`. It lives in ahg-core because `packages/ahg-ric/` is a locked path.

`php artisan ahg:provenance-ai:migrate-star` is a dry run by default. The prod dry run on 30 September counted 3,472 graphs, 3,472 statement nodes and 17,360 triples to insert, with nothing skipped. `--apply` on `ric`, then on `--endpoint=http://localhost:3030/openric-model` (5 graphs), is still to be run. Dev and prod both point at the same `localhost:3030/ric`, so an `--apply` from dev changes live data.

## heratio#1448: Local Contexts Hub, blocked on credentials

The Hub API is v2 (OpenAPI at `https://localcontextshub.org/api/v2/schema/?format=json`), keyed by `X-Api-Key`, with a separate sandbox at `sandbox.localcontextshub.org`. The client had called v1. Label matching could never have worked, because it compared local codes such as `tk_a` with Hub types such as `attribution`; there is now a map, keyed on family as well as type because TK and BC share several type names. A v2 `community` object had been stored as the string "Array". Live sync still needs a registered project, an API key, and two config values (`local_contexts_project_ids`, `local_contexts_hub_url`) that are not on the settings form yet.

## heratio#1514: CAAIS profile and the gap audit

The CAAIS 1.0 profile sits in side tables keyed on `accession.id` (`packages/ahg-accession-manage/database/install_caais.sql`), with nine `caais_*` Dropdown Manager taxonomies. It is switched on under Admin > AHG Settings > Accession and exports JSON with a crosswalk block, because the CCA publishes no XML schema or JSON binding. The provider self-installs the tables on first boot.

The audit is posted on the issue. Four findings contradict what had been assumed:

- **Custom fields** reach no export and no description page, and `CustomFieldService::getValues()` queries columns its own `install.sql` does not create.
- **SSO** is UI stubs pointing at a route (`oidc.login`) that does not exist.
- **The dedupe merge** only sets a status.
- **The accessibility statement** cites a test file that does not exist.

SSO and WCAG are waiting on decisions: which protocols, and whether to commission an external audit.

Two bugs turned up in passing. The accession form discards its Events table (heratio#1520). The accession page shows donor email and city as ciphertext, because `AccessionService::getDonorContacts()` skips the decrypt that `DonorService::getContacts()` does (heratio#1521).

## Operational lessons

- `bin/release` commits every change in the tree. For separate releases per issue, the tree has to hold only that issue's work. Otherwise do one release that names every issue.
- `bin/check-locked` scans the whole tree, and a successful release clears the entire `.git/UNLOCKED` list.
- An unlock entry must match the `.locked-paths` spelling exactly, including the trailing `/` on directory rules. `packages/ahg-ric` without the slash is a silent no-op.
- Parallel subagents in one tree sharing a scratchpad overwrote each other's temp files. Give scratch files unique names, or give each agent its own worktree.
