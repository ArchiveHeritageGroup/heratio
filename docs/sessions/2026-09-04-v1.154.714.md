# v1.154.714 (2026-09-04)

fix(privacy,tests): redaction masks land where the cataloguer drew them, on the deep-zoom viewer and on rows stored in either coordinate shape. TWO KEY SHAPES: privacy_visual_redaction.coordinates is written by the editor as left/top/width/height, but rows exist as x/y/width/height - five of each on dev - and only the editor's own loader ever read both, via left ?? x. Three consumers did not, and each failed differently. The public overlay read coords.top and coords.left alone, so an x/y row gave undefined, undefined times width gave NaN, and the browser dropped the top and left declarations while keeping width and height: the mask drew at the correct size over the wrong part of the image, which is worse than not drawing because the page looks redacted. RedactionRenderService, which burns masks into derivative files, read top and left with no fallback and defaulted both to zero, so the mask was baked into the top-left corner of a file that then gets served. The audit snapshot diffed two rows describing one rectangle as different, in a method whose stated purpose is a stable shape. All four now read PrivacyService::redactionRect(), one reader rather than the fallback chain repeated in PHP and again in JavaScript. All ten stored rows resolve to true coordinates; half previously resolved to the origin. DEEP ZOOM: a tiled viewer has no img to measure and its own pan and zoom, so the overlay found no element and returned, and the viewer used for high-resolution archival scans showed the unredacted scan to the public. OpenSeadragon places overlays itself in viewport coordinates and keeps them aligned through every transform, so the fix hands it the rectangle rather than computing pixels. Verified against a real tiled viewer rather than reasoned about: masks land at the exact requested fraction and hold through a 3x zoom and pan, the plain-image path lands exactly after a mode switch, and Mirador is hidden with a notice. FAIL CLOSED: a canvas viewer this shim cannot mask no longer simply shows the record. Mirador is the remaining case, a second tiled viewer with its own overlay model, so it is hidden rather than left open; the deep-zoom viewer is hidden only if placing its overlays actually failed. The browser caught a race in the first attempt at that guard - the paint helper returned false both for failed and for not-open-yet, so it would have hidden a healthy viewer between the mode button and the first tile. It now reports absent, pending, ok or failed and hides only on failed. Mode buttons re-run enforcement, which nothing did before, so switching viewers no longer leaves stale or unpainted masks. TEST SUITE: packages/ahg-mva-claims is a symlink into a separate application, and the All suite's packages glob followed it into tests extending a base class that package's autoload-dev supplies and a path repository does not merge, so suite construction aborted before a single test ran. That is why All had not worked in months, and why the ahg-privacy tests sat unrun. Excluded, as ahg-z3950 already is; PHPUnit ignores an exclude path that does not exist, so the line is inert on instances without the symlink. All now builds and runs 1348 tests, of which one error and two failures are pre-existing and sit in packages no suite covers. ahg-information-object-manage had no tests at all; it has seven now, on the shared reader, and is in the Package suite. 398 Package tests pass, up from 391, and 286 Feature tests pass.
