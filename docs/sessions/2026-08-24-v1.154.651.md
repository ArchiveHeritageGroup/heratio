# v1.154.651 (2026-08-24)

fix(acl,landing-page,gallery,user-manage): audit trails written and never read, row blocks with no children, and three orphan views - #1478. Baseline 67 -> 43. TWO AUDIT TRAILS EXISTED AND NO SCREEN SHOWED THEM. user_security_clearance_log has been written on every grant, update and revocation since it was added and never once read: userClearance() set $accessHistory = collect(), a hardcoded empty collection, so the history panel was blank while 5 rows of real audit sat in the table. Now joined to security_classification and user so the panel shows what changed and who changed it. objectView() likewise hardcoded $objectClassification = null, so the Object Security Details page showed nothing about the object's security - the single thing that page exists to display. Now joined for the classification name, colour, timestamp and the username of whoever set it. NOTE that join is correct but UNPROVEN against data: object_security_classification is empty on dev, so I verified the query shape and not a populated result. LANDING PAGE ROW BLOCKS had no children. getPageBlocks() returns only top-level blocks (whereNull parent_block_id) and never attached descendants, while the row_1_col, row_2_col and row_3_col templates - whose entire purpose is holding children - read $block->child_blocks. Every row rendered empty. Children are now fetched in ONE query and grouped by parent, not one query per row, and ordered by column_slot then position. Verified against real data: row_1_col blocks show 1 child, row_2_col blocks show 2. Its sibling finding, computed_data, is NOT fixed and is not a wiring bug: that value becomes the $data each block partial receives, and computing it means a per-block-type resolver that does not exist - a feature, not a rename. GALLERY FACILITY REPORTS had bindings matching no column: climate_control against climate_controlled, fire_safety against fire_detection, report_date against completed_date, institution against institution_name, is_approved against approved, type against report_type, and a bare security against a table that records security_24hr, security_guards, cctv and intrusion_detection separately. Every binding in both views now resolves to a real column, checked one by one against information_schema. THREE ORPHAN VIEWS DELETED, 9 findings of dead code: ahg-rights-holder-manage/extendedRights/_rights-display (its would-be parent _extended-rights-area, also deleted, included ahg-extended-rights::_rights-display which does not resolve - the real file is under partials/ in another package - so the include would have thrown; the LIVE rights view uses a different and working $rightsData shape) and ahg-acl/security/object.blade.php, an orphan duplicate of the object-view that IS rendered. Deleted only after confirming each is rendered by no controller and included by no blade. THREE DEAD ALTERNATES REMOVED rather than wired: index-actor-acl, index-information-object-acl and index-repository-acl read $permission->access_label ?? ($permission->grant_deny ? 'Grant' : 'Deny'). acl_permission has grant_deny and no access_label, so the fallback was already correct and access_label never ran - the dead prefix is gone and the code now says what it does. A CAUTION FOR THE NEXT PASS: I built a heuristic to find orphan views by grepping for the basename and it flagged the landing-page block templates as unreferenced. They are not - they are reached through a DYNAMIC include, @include('ahg-landing-page::blocks.' . $templateName). Had I trusted it I would have deleted live templates. Every deletion in this release was confirmed by hand instead. 245 Feature tests pass.
