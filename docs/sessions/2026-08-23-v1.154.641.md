# v1.154.641 (2026-08-23)

fix(privacy,museum,ai): the PII scan screen never showed a single finding, and the museum Object Template pills were never wired. PII SCAN RESULTS has reported 'No PII detected in this record' and 0/0/0/0 for EVERY record since it was written. PrivacyController::piiScanObject() does array_merge($scanResult, $r) where PiiScanService::scan() returns a flat LIST of findings and the view reads $scanResult['entities'], ['summary']['total'], ['high_risk'] and ['risk_score'] - so the numeric keys were appended where nothing reads them and 'entities' stayed empty. A screen reporting a clean bill of health on a record containing five identity numbers, a card number and an email address is worse than one that errors. New shapeScanResult() builds what the view actually reads: entities with type/value/confidence/risk_level, a summary, and a capped risk score. Bands follow the confidences the scanner really emits - 0.95 Luhn-valid card, 0.92 email, 0.90 checksum-valid SA ID, 0.80 phone, 0.55 date of birth, 0.30 for an ID whose checksum FAILS - so high means 'the pattern validated', medium 'matched but unverified', low 'shape only'. NOTE the first cut of that method emitted 'risk' while the view reads 'risk_level', so every row rendered as the ?? 'low' fallback and a 90% match was badged Low: the #1478 defect, committed inside the fix for it, which is why there is now a comment at that line. Blade gains CREDIT_CARD and IP badge colours. MUSEUM OBJECT TEMPLATE: the /museum/add sidebar offers General, Painting, Sculpture, Photograph and Textile as javascript:void(0) anchors with data-template attributes - and no handler was ever bound, with 'active' hardcoded on General, so four of the five could not be selected at all. The sidebar was copied from the gallery form without the behaviour that drives it; gallery has the handler at edit.blade.php:1885 and sets its active pill from $__tpl. Ported it, toggling in place rather than reloading for the reason the gallery view already documents (nothing server-side is template-conditional, so a reload only reverted the pill and risked discarding half-entered input), plus the hidden template field the handler needs somewhere to write to. The choice is submitted but still inert on save - MuseumService writes an explicit column whitelist - which is honest and stated in the markup rather than implied. NER: ahg:ai-ner gains --ids= for targeted extraction. The sweep orders by information_object.id ascending, so re-extracting one record - after a correction, or to prepare a demonstration - meant walking every lower id first and spending gateway quota on records nobody asked about. NEW ahg:privacy-seed-demo-pii seeds clearly-labelled synthetic PII for POPIA demonstrations. Every identity number uses citizenship digit 2, which Home Affairs never issues (only 0 citizen and 1 permanent resident), so none can belong to a living person - while validateSaIdNumber() checks shape, all-zeros sentinel and Luhn only, so detection behaves exactly as it would on real data. Both checksum-valid and checksum-broken numbers are seeded, putting 0.90 and 0.30 in one document. Card is 4111 1111 1111 1111, the reserved test PAN. Records are titled [SYNTHETIC], carry a banner explaining the citizenship-digit trick, and are seeded DRAFT so they are not publicly reachable. Playwright 'talk' project added: captures each screen twice, authenticated and anonymous, because a privacy demonstration showing only the staff view proves nothing about what the public can reach. Released as .641 after a concurrent .640 collision; rebased onto that commit. 242 Feature tests pass; tools/scan-blade-bindings.php --check reports no new findings.
