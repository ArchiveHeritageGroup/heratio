# v1.154.631 (2026-08-21)

fix(ner): close the extraction ledger - #1472. ahg_ner_extraction recorded that a scan STARTED and never what became of it: AiController::saveExtraction() inserted status='pending' hardcoded, never wrote entity_count, and nothing anywhere updated either column (one INSERT and five SELECTs across the repo, no UPDATE), while NerService::createAccessPoints() - the path ahg:ai-ner and ahg:ai-process-pending use - did not touch the table at all. So the ledger showed 192 rows stuck 'pending' with 0 entities and nothing completed since 25 January, and NER looked dead for seven months while 2,108 entities sat in ahg_ner_entity all along. Not cosmetic: PiiScanService derives the POPIA statistics from exactly those two columns, so the privacy surface reported 24 objects containing PII when 47 do, and 454 entities against 2,108 stored. New AhgAiServices\Support\NerExtractionLedger is the single writer for both paths, because two implementations of the same write are what produced the divergence. Status vocabulary keeps the cases that matter apart: running (opened, outcome unknown), completed (finished - entity_count 0 legitimately means scanned-and-found-nothing), failed (the scan itself threw, NOT a clean scan), and pending now means legacy-row-of-indeterminate-outcome that new code never writes. Backfill migration attributes each historical run its OWN entities via ahg_ner_entity.extraction_id: dev went 45 completed/454 entities to 78 completed/2,108, reconciling EXACTLY with the 2,108 rows stored, and privacy_with_pii 24 -> 47 matching the 47 objects that genuinely have entities. Rows with no linked entities are left 'pending' rather than assigned an invented outcome. NOTE a first draft of that migration fell back to per-OBJECT counting when a row had no link and applied an object's total to every one of its extraction rows - 237 rows over 66 objects - inflating the ledger to 13,328 against 2,108 real; caught by reconciling against ahg_ner_entity before shipping, and the migration is now idempotent and self-correcting. Verified live: ahg:ai-ner now writes ledger rows (0 before) and closes them completed. 231 Feature tests pass
