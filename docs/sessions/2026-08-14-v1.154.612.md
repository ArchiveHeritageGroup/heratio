# v1.154.612 (2026-08-14)

fix(cron): twelve scheduled commands invoked options their command has never defined, so none of them had ever run. ahg:backup --components/--retention, preservation-identify --unidentified, preservation-virus-scan --quarantine, preservation-replicate --verify, preservation-obsolescence --risk-level, qdrant-index and qdrant-image-index --db-user, dedupe-scan --threshold, museum-aat-sync --depth, privacy-scan-pii --jurisdiction, and queue:retry --all (Laravel takes 'all' as an argument). Each died on 'The --X option does not exist.' every run: scheduled backups, virus scanning, replication, obsolescence review, vector indexing, duplicate detection, AAT sync, PII scanning and queue retries were all configured and none had executed. Seed corrected in CronSchedulerService AND a migration repairs existing cron_schedule rows - correcting only the seed is what left workflow-process still failing on all three instances after v1.154.602, since the stored row is what actually runs. The migration validates against each command's REAL definition rather than a hardcoded list, so it catches future drift too, and is conservative: it strips only the unknown option and keeps the valid ones, so a command runs with its own defaults instead of not running at all. Verified: 14 invalid options before, 0 after, and workflow-process, preservation-identify, museum-aat-sync and dedupe-scan all now exit 0 - dedupe-scan found 100 duplicate groups on its first ever run
