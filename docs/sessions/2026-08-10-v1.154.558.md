# v1.154.558 (2026-08-10)

fix(iiif): Content Search returned zero hits when OCR was linked to a derivative. IiifContentSearchService::buildCanvasMap keyed the canvas map only by MASTER digital-object ids (object_id=IO), but OCR is normally run on the reference/thumbnail DERIVATIVE (the master is often a PDF/TIFF Tesseract can't read), so iiif_ocr_text.digital_object_id was a derivative id that never matched the map -> the empty-canvas-map guard returned an empty AnnotationPage for every query. buildCanvasMap now also maps each master's derivatives onto the master's canvas, so a hit on a derivative resolves to its canvas. Verified end-to-end: OCR'd a real page image (ahg:ocr:page --persist), search(Summit) now returns an annotation with the correct canvas IRI + FragmentSelector xywh coords, autocomplete returns the term. (Autocomplete already worked - it doesn't use the canvas map. Anon content-search stays published-only per #1363.)
