# v1.154.619 (2026-08-16)

fix(doi): stop hammering DataCite with credentials that cannot work. ahg:doi-mint runs without --dry-run on its schedule, so heratio.org attempted 50 live mints a night and every one came back HTTP 404 'the resource you are looking for doesn't exist'. The cause was configuration, not the API: five active ahg_doi_config rows, all carrying prefix 10.12345 - DataCite's DOCUMENTATION placeholder, registered to nobody - and four of the five with no password at all. A placeholder prefix cannot mint, so each record failed identically and the real reason was buried under an API error that never mentioned it. DoiService now rejects a config that cannot authenticate (no password, or the 10.12345 placeholder) before any request is made, naming what is missing, and the command stops on the first such result instead of walking the whole batch into the same rejection and reporting it fifty times. Verified: exits 0 with 'DOI minting is not configured: prefix is DataCite's documentation placeholder' and issues no HTTP call. Real DataCite credentials remain an operator action - this changes only how the absence is reported
