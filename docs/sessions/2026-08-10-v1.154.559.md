# v1.154.559 (2026-08-10)

fix(iiif): Auth 2.0 probe never gated restricted resources (open to all). resolveClearanceRequirement() matched the manifest slug with preg_match('#/iiif-manifest/([^/?#]+)#', ...) - but the character class contains a literal '#', which closes the '#'-delimited pattern early and throws 'Unknown modifier', so preg_match returned false, the method returned null (no requirement), and the probe answered 200 Access granted for EVERY resource including restricted ones. Switched the delimiter to '~'. Verified end-to-end: with an iiif_auth_resource row the probe now returns 401 Authorization required + the AccessService block (viewer prompts login); without one it returns 200; toggling the row flips it. No other delimiter-conflict regexes in the file. (Content Search validated + fixed separately in v1.154.558.)
