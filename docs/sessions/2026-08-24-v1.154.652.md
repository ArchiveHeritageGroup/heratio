# v1.154.652 (2026-08-24)

fix(io-manage,heritage,marketplace,acl,accession): five orphaned AtoM-migration views, a stubbed page, and the last easy renames - #1478. Baseline 43 -> 24; 101 when the issue was filed. FIVE ORPHANED VIEWS DELETED (8 findings of dead code): _event, _related-events, _related-material-descriptions, do-edit and digitalobject/edit in ahg-information-object-manage. All are AtoM-migration leftovers superseded by digitalobject.edit-page, which is what DigitalObjectController:798 actually renders. Their findings were the Propel accessor names that migration left behind - eventsRelatedByobjectId, relationsRelatedByobjectId, canThumbnail, displayAsCompoundObject - which could never resolve under Laravel. Each was confirmed rendered by no controller, included by no blade, and reachable by no dynamic include before deletion. This also shrinks the display_as_compound surface on #1481 from three views to one. MY ACCESS REQUESTS was a one-line stub returning ['items' => collect()], so the page showed nothing however many requests a user had made - and the view loops $requests, not $items, so even a populated 'items' would not have rendered. Two faults, either one enough on its own. Now queries heritage_access_request for the signed-in user, joined for the object title and slug. purpose_name falls back to the requester's free text because heritage_access_purpose carries no name column on this schema - the honest label rather than an invented one. MARKETPLACE LISTING breadcrumb: the page builds its category link from category_slug and marketplace_listing stores only category_id, so the link pointed nowhere on every listing. Joined marketplace_category for slug and name, folded into the same getListingById() that carries the auction join - the auction branch now addSelect()s so it no longer discards the category columns. THE 2FA BADGE ON THE CLEARANCE PAGE was asserting something false. user_security_clearance records no two_factor_verified and no two_factor_verified_at, so the affirmative branch could never run and every clearance displayed a 'No' badge - stating that two-factor was NOT verified when the truth is that it is not tracked at all. Absent and negative are different states. It now reads 'Not recorded' with a tooltip; restore the yes/no when the columns exist. RENAMES against real columns: wall_length to wall_length_m (gallery_space), geo_cultural_context to geocultural_context (repository_i18n), valuator_name to valuer (accession_valuation_history), and accession attachment size_display now derives from file_size rather than reading a column that never existed. DEAD ALTERNATE REMOVED: errorLog read $entry->url ?? $entry->request_url; ahg_error_log has url and no request_url, so the correct name was already first and the alternate never ran. THE SCANNER LEARNED SOMETHING: it now treats a property the view ASSIGNS to itself ($row->checklist_name = ... a few lines above the read) as produced. Two findings were false positives of exactly that shape, and a tool that reports false positives trains people to ignore it. 245 Feature tests pass.
