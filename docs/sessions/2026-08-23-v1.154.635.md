# v1.154.635 (2026-08-23)

feat(library): scope circulation to the operator's branch - #1473 Phase 2, and fix a third silently-wrong screen. Phase 1 gave every transaction a branch; nothing said which branch the person at the counter was standing in, so the desk and the overdue list still showed the whole service to everyone. Nothing was reusable: no user-to-repository link exists anywhere in the schema, and the nearest thing - ahg_tenant.repository_id - maps an entire TENANT to one repository, which is the wrong grain because a multi-branch service is ONE tenant with MANY branches; binding operator scope to the tenant would have made the branch axis unreachable for exactly the deployment it was built for. New library_staff_branch holds one row per user - a home branch plus an all_branches flag for the consortium supervisor who genuinely needs to see across outlets. One row per user rather than a many-to-many roster, because the question is 'where is this person working now', which has one answer at a time; a rostering model can replace it later without breaking callers, since every read goes through LibraryBranch rather than touching the table. No admin screen, deliberately: the operator picks their branch from a selector on the circulation desk, the choice holds for the shift in session and is persisted so the next sign-in starts at the same counter, so covering another branch for an afternoon does not require an administrator and there is no half-built settings page to find first. The selector appears only where the branch axis exists AND more than one repository is defined - a single-outlet service is not asked to choose between one option, which reads as an unfinished setting. It sits behind plain auth rather than acl:update, because choosing where you are standing is not a change to catalogue data and a read-only staffer still needs their lists scoped to their own counter. THE DISTINCTION THE WHOLE PHASE TURNS ON: operatorBranchId() returning null means EVERY branch - both the consortium view and a single-outlet service that has never named a branch - and must never be read as an empty scope, or every existing installation goes blank on upgrade; operatorSeesAllBranches() exists solely to word those two states differently on screen. History does not vanish either: a loan made before Phase 1 has branch_id NULL, and filtering strictly on the checkout's own branch would have dropped every historical loan out of its branch's list the moment scoping was switched on, which looks exactly like data loss at the counter - so scopeToBranch() matches a loan whose own branch is the one asked for OR one with no branch whose copy is shelved there, pinned by a test. THIRD INSTANCE OF ONE PATTERN IN TWO DAYS: overdue.blade.php bound $o->patron_name, $o->days_overdue and $o->fine_amount, and listOverdue() selected none of the three - it returns first_name, last_name, due_date, barcode, call_number and title. The Overdue Items screen has therefore shown a BLANK PATRON, 0 DAYS OVERDUE and 0.00 FINE on every row for as long as it has existed. Two of the five columns worked (Item, Due), which is why it survived - the table looked alive. #1477 was the loan-rules screen, the checkout preview was about to become the second, this is the third: a Blade view bound to properties its query does not produce, failing silently into a fallback instead of erroring. All three are now derived properly; listOverdue() computes them in PHP rather than SQL because the library package's tests run on SQLite, where DATEDIFF and CONCAT are unavailable. One deliberate change of meaning: fine_amount is now NULL, rendered 'Not yet calculated', where no fine row exists - a fine accrues on return or on the nightly run, so that is a real state and is not the same as nothing owed, and printing 0.00 was misleading. Core-schema mirror extended for library_staff_branch (CREATE TABLE IF NOT EXISTS, idempotent, verified loading twice against heratio_test). Both views rendered and inspected: the desk selector offers 15 repositories plus 'All branches' with the current one selected, and the overdue table renders a real patron name, a real day count, and the not-yet-calculated state. STILL OPEN on #1473: branch-aware notices (LibraryOverdueNoticeService still sends as one library from one address), hold routing and queue position per pickup branch, an admin editor for branch loan rules, scoping patron browse and the circulation reports, an administrator override forcing a staffer to one branch (today any operator may select any branch - fine for a public-library service, not for a consortium with contractual separation), and dropping the legacy library_copy.branch / library_hold.pickup_branch text columns. 440 tests pass (242 Feature + 198 ahg-library, 30 skipped).
