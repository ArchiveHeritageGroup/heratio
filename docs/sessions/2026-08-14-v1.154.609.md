# v1.154.609 (2026-08-14)

fix(deploy): restart queue workers as part of the deploy, and correct three cron lock paths in the repo. Queue workers are long-lived PHP processes that load the application once and keep serving jobs from that copy, so a deploy left them running the PREVIOUS release indefinitely - restarting php-fpm does nothing to them. On 2026-08-14 an Archivematica fix was deployed, confirmed present in the file, and kept failing because the job that used it runs on the queue and dev's worker had been up nearly nine days on pre-fix code; anything queued (DIP ingest, normalization, webhook delivery, exports) had the same exposure. heratio-deploy.sh now runs queue:restart after migrate/caches, which is graceful - each worker finishes the job in hand, exits, and systemd starts a fresh one - and tolerant of an instance with no worker running. Separately, the drift check earned its keep: deploy/cron/heratio-schedule, ahg-facet-cache and ahg-discovery-prune all specified /var/run/*.lock while the live copies use /run/lock/*.lock. /var/run resolves to /run, which is root-owned 755 and NOT writable by www-data, so flock would fail and all three jobs would silently never run on any host rebuilt from the repo. Repo aligned to the working live copies; drift clean at 14 files
