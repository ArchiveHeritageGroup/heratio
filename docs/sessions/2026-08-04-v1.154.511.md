# v1.154.511 (2026-08-04)

feat(#1447): Phase 1 - attach multiple digital objects to one description (no child records). New information_object_digital_object link table: the existing single primary digital_object (object_id=IO) is left UNTOUCHED so every legacy object_id read keeps working; additional objects are ordinary digital_object rows with their own thumbnail/reference derivatives (parent_id) whose object_id is NULL - invisible to legacy reads - linked only via the table (sort_order, is_primary, caption, role). New AhgCore\Services\AttachedDigitalObjectService (attach reuses DigitalObjectService::upload then detaches object_id; listFor; detach cascades master+derivs+files). DigitalObjectController::attachStore (multi-file, deny-list + quota checks) + attachDelete; routes io.attachments.store/delete. Self-contained _attached-objects gallery partial on the archival show page: thumbnail grid (derivative-only for anon), editor-gated multi-file attach form + per-item remove. Core-schema mirror added. Verified: attach creates master(object_id NULL)+2 derivs, listFor works, legacy primary UNCHANGED, detach cleans up, partial renders. Phase 2=exports (IIIF/EAD/RiC), Phase 3=DAM/museum/gallery/library
