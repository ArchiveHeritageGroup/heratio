# v1.154.587 (2026-08-12)

feat(deploy): #1465 bin/check-config-drift - detect when tracked host config stops matching the box, and reconcile the five drifts it found. The repo already tracked deploy/ and config/cantaloupe/, but nothing verified the copies still matched, which is how the nginx IIIF snippet drifted in BOTH directions until neither side was correct. bin/check-config-drift compares 14 tracked files against their installed counterparts and exits non-zero on drift, so it can run from cron or CI. Three comparison modes: exact (byte-for-byte mirrors - sbin scripts, cron files, vhosts), rendered ({{HTTP_PORT}} substituted before comparing the IIIF snippet template), and inform (delegates.rb is generated per host then MERGED with every other instance's entry, so it can never equal the single-entry template - reported for eyeballing, never fails). A file not installed on this host is SKIPPED rather than failed, since not every box runs every vhost. IT FOUND FIVE PRE-EXISTING DRIFTS ON ITS FIRST RUN, all now reconciled with the LIVE copy as the source of truth because in every case live was right and the repo was stale: (1) deploy/nginx/heratio.org.conf was missing the dedicated php-fpm socket from the #1446 pool isolation and two facet-crawl-guard includes - the tracked copy of PROD's own vhost predated a shipped change; (2) deploy/nginx/heratio.theahg.co.za.conf still held a full 275-line app vhost when that domain has been converted to a 31-line 301 redirect to heratio.org - which also explains why heratio-deploy.sh's health check against it returns 301 rather than 200; (3) deploy/cron/ahg-facet-cache still looped over 'archive atom dam heratio' where live runs 'dam heratio', deliberately narrowed when atom was stopped (there is a .bak-pre-atom-stop-20260804 beside it); (4,5) deploy/cron/heratio-schedule and ahg-discovery-prune carried a 'Tracked copy of ...' annotation header the live files lack - which is itself drift by this check's own definition, so the headers are stripped and documentation stays in READMEs, keeping mirrors byte-exact the way deploy/sbin already does. Checked the newly-synced copies for secrets: none. The failure message deliberately does NOT assume the repo is authoritative - it says to decide which side is right, because today the answer was 'live' in all five cases
