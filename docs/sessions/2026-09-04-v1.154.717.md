# v1.154.717 (2026-09-04)

fix(privacy): only a passed checksum may declare a category of personal data. A national identifier whose check digit FAILED used to drop to 0.3 confidence, band low, count toward the risk score, and enter categories_of_data on an Article 30 record - a legal document asserting the institution processes national identifiers, on the strength of a value the scanner had itself just disproved. It is now banded review: still surfaced, because a reviewer should see a number that looks like an identifier and is not one, but contributing nothing to the tallies or the score and structurally incapable of creating a compliance assertion. Same treatment custom_term received at v1.154.710, and for the same reason - confidence measures how sure the MATCH is, never whether the thing is what it appears to be. The finding now carries a validated flag with THREE states, and the third is the one that matters: true means a checksum ran and passed, false means one ran and failed, null means no checksum exists for that jurisdiction. Only true may assert. Reading null as a failure would silently mute every jurisdiction without a validator, which today is most of them - popia is the only national-ID pattern here that has one - so null is explicitly not a failure and is tested as such. Three places enforce it and the third needed care: ComplianceAutopilotService barred non-category findings by TYPE, but this is not a property of the type, since the same national_id type produces both, so it is read off the finding instead and NON_CATEGORY_TYPES now records why the two mechanisms coexist. Blast radius checked rather than assumed. Findings are stored as JSON so there is no schema change, and rows written before today carry no validated key at all: they read as null and keep the band they already had, so no existing compliance artefact reclassifies. Proven against data - all 17 stored findings on dev band identically, 7 high 6 medium 4 low, none moved - and pinned by a test. Verified end to end on a real scan: 8001015001084 passes Luhn and bands high at 0.90, 8001015001080 fails and bands review at 0.30. The view needed no change beyond widening a comment that said operator watchlist matches and would now have been wrong; the review band already had its colour and tile. Raised by a sibling instance working the same ground on PSIS, whose rule is that only a checksum sets validated and only a validated finding may create a compliance assertion - worth adopting before the ndpa and kenya_dpa patterns arrive rather than after, since a context gate is evidence about surrounding prose and not about the value. 1052 Package tests pass, up from 1047, and 286 Feature tests pass.
