# v1.154.613 (2026-08-14)

fix(3d): 3D derivative generation never found a single master - 'uploads/uploads' in every path. ThreeDThumbnailService built the master path by concatenating config('heratio.uploads_path') with digital_object.path, but the configured base already ends in '/uploads' while the stored path begins with '/uploads/r/<id>/', so every lookup went to .../uploads/uploads/r/<id>/ and every file was reported missing. ahg:3d-derivatives therefore ran on schedule and failed all eight models on every pass, logging a failed scheduled command each time; the multiangle output directory was mis-derived the same way. Both sites now resolve through AhgCore DigitalObjectService::resolveDiskPath, which strips the duplicated segment while KEEPING the r/ shard and carries the legacy-layout fallbacks - the same resolver, and the same bug class, as #1455. Verified on dev: processed=8 success=8 failed=0, previously success=0 failed=8. Not fixed, and not a defect: refresh-facet-cache failed twice on prod with a lock wait timeout, which is contention - it completes cleanly on demand, rebuilding 558,297 rows
