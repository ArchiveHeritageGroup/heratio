# v1.154.668 (2026-08-25)

feat(heritage): implement the two analytics stubs - #1478 reaches ZERO findings. Both were one-line stubs returning ['stats' => [], 'records' => []] while their views read entirely different variables, so each rendered its empty state on every request. ANALYTICS-SEARCH is fully real, from ahg_search_query_log: popular queries, zero-result queries, day-of-week patterns and click conversion all come from recorded searches. click_position is null when nothing was clicked, so counting non-null rows IS the click count. Trending compares the last seven days against the seven before, and a query with NO prior searches is deliberately excluded rather than reported as growth - +100% for a single first-ever search would be the most misleading figure on the page. ANALYTICS-CONTENT is split by what this instance can actually know, which is the point. The quality checks are computed from the records themselves and are real: of 298 published records, 25 have no scope and content, 22 have nothing digitised, and 25 have neither extent nor access conditions - 72 issues. Views, downloads and click-through are NOT knowable: there is no view- or download-tracking table of any kind here. They return null and render 'Not tracked' rather than 0, because 0 reads as a measurement meaning nobody looked, which is a different and false statement - the same distinction as the two-factor badge earlier in this issue, where absent and negative were being conflated. broken_links is a type the view colours but nothing produces: finding a dead link means fetching every URL in the corpus, which is a scheduled job and not something a page load may do, so it is absent rather than faked. I NEARLY SHIPPED A #1478 DEFECT INSIDE THE FIX FOR #1478. I passed $qualityIssues as its own view variable; the view rebinds it from $contentData['quality_issues'] in its own @php block, silently overwriting mine with an empty array. The controller returned 72 issues and the page displayed none, with nothing erroring. It was caught by grepping the RENDERED HTML rather than trusting the controller's return value - which is the entire lesson of this issue, and I needed it. Baseline regenerated empty; the CI gate now holds a ceiling of zero. 225 Feature tests pass.
