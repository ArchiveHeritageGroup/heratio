# v1.154.771 (2026-09-18)

fix(backup,provenance-ai): binlog 
  archiving has never worked, so point-in-time recovery does not exist - /var/lib/mysql is 0700 mysql:mysql and www-data cannot read it however many groups it is in, so is_readable() was false for every
  log on every hourly run and /mnt/nas/heratio/backups/binlogs has held 0 files since 13 August while emitting ~1,170 warnings an hour. BinaryLogArchiver keeps the filesystem copy as the fast path and 
  falls back to mysqlbinlog --read-from-remote-server --raw, which needs no datadir access and no new grant because the configured user already has it; credentials go in a 0600 defaults-file, never 
  argv. Per-file warnings collapse to one INFO per run plus one ERROR naming PITR when a log truly cannot be fetched. New --max-files cap, default 50, because the untouched backlog is 1,171 logs / 79 GB
  and one tick pulling that would hold withoutOverlapping() for hours. Separately, FusekiReplayCommand invoked OverrideService::buildOverrideTurtle() with the row object although it takes six scalars -
  method_exists() checks the name, not the shape - so every override replay threw a TypeError; now mapped properly including inference_id to inference uuid, behind an arity guard that degrades to the 
  existing fallback. Verified on dev: 2 logs archived over the protocol with the cap honoured and zero per-file spam; ahg-provenance-ai 10/10.
