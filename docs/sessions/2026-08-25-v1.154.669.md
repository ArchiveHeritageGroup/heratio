# v1.154.669 (2026-08-25)

fix(nginx): make the facet-crawl guard actually fire on Heratio - #1484. snippets/facet-crawl-guard.conf is included in the Heratio vhosts and has never once fired on one. It 429s $is_crawler AND $has_facet_params, and $has_facet_params matches AtoM's ARRAY facets (creator%5B0%5D=) while Heratio builds flat scalar facets (maintainedBy=, entityType=, displayMode=, hasDigital=, topLevel=). Of 36,157 requests to /actor/browse on 2026-08-24, not one could match. A control that reads as present and correct in the config, protecting nothing, in the file whose whole purpose is the problem it was missing. WHAT IT WAS MISSING: 2,682 requests from declared bots on faceted browse URLs, 2,361 of them Baiduspider, plus Googlebot at 193 and bingbot at 156. THE RULE MATCHES PARAMETER COUNT, NOT NAMES. Four or more query parameters. A name list goes stale the first time a filter is added and the facet space differs per application and per endpoint; the count is the shape of combination-walking itself. Measured on a 2,000-URL sample of real browse traffic: 1,834 carried SEVEN or more parameters. The threshold is 4 so a language switch plus pagination plus one filter is still allowed. Verified across the matrix - declared bot with 4 params 429, declared bot with 1 param 200 so language variants and shallow pages stay crawlable, and an ordinary browser with 4 params 200, because the rule only ever applies together with $is_crawler and a human paging through filters must not be refused. I GOT THE COLLATERAL CHECK WRONG FIRST AND AM RECORDING IT. I initially added the pattern to the shared conf.d/bot-blocker.conf map, having checked for impact by measuring what bots had HISTORICALLY requested on the AtoM vhosts - all of it under 4 parameters - and read that as proof the rule would not affect them. Those are different questions. A live probe then showed Googlebot receiving 429 on a legitimate atom.theahg.co.za browse URL: a crawler-policy change on instances belonging to another project, which was not mine to make. Reverted, and the shared file is now byte-identical to its backup. The rule is defined in conf.d/heratio-browse-shed.conf and referenced only from the Heratio vhost, so sasa and the AtoM instances are untouched - confirmed live. NOT FIXED BY THIS: the distributed scraper behind the original incident sends plain Chrome user agents and is not $is_crawler by any definition. Shedding (v1.154.662) is what protects capacity there; this disciplines the honest crawlers, which are a real and measurable share of the load. Unrelated but observed while testing: atom.theahg.co.za is returning 80-99 5xx per hour, roughly 80% of its traffic, since at least 01:00 and independent of any change here.
