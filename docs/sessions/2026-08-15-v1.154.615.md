# v1.154.615 (2026-08-15)

fix(cron): first unattended night after the schedule repairs - nine commands met real conditions for the first time. Not-configured reported as failure, now exit 0 with a clear message: ai-condition-scan (documented open decision #1268), ai-htr (HTR service not deployed), oai-harvest (no repositories configured). Unschedulable by nature, now disabled by default in the seed: 3d-multiangle requires --id/--object-id and ai-translate requires --to, and neither has a batch mode, so requiring the argument interactively is correct and a nightly run was meaningless. REAL bug, backups had never been written: ahg:backup built mysqldump with no credentials at all, on the assumption of socket auth - true for an operator running as root, false for the scheduler running as www-data, which holds no MySQL grant, so every scheduled backup died with 'Access denied for user www-data'. It now takes credentials from the application's own DB config and passes the password via MYSQL_PWD rather than --password so it is not exposed in the process list, with the dry-run output redacted. Verified: 29.8 MB dump written as www-data. REAL bug, preservation-replicate had never run: it named four columns that do not exist - target.kind (is target_type), package.bag_path (is export_path), event.package_id and event.detail/outcome (are event_detail/event_outcome, with no package FK at all) - and filtered on a package status value ('completed') the column never takes. Query rewritten against the real schema, matching events through the JSON the command itself writes; now finds both packages. Atom-database family extended: authority-completeness-scan, authority-ner-pipeline and doi-mint all defaulted to the 'atom' connection - doi-mint hard-coded it with no override - so all three were denied on sasa every run. New AhgCore Support DiscoverySource holds that resolution once instead of a fourth copy, and an unusable source now reports and exits 0
