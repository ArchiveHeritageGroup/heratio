# v1.154.521 (2026-08-05)

fix(#1457): multi-object viewer uses plain reference images, not the broken Cantaloupe service. v1.154.520's Mirador pointed at the /iiif/ manifest, but Cantaloupe 404s these paths (misconfigured root) and 501s webp - so the canvases would render broken. Reworked: _digital-object-viewer builds the object list from each master's PLAIN reference JPEG (getUrl of the 141/142 derivative) - anon-safe, and sidesteps both the webp-501 (references are JPEGs) and Cantaloupe-404. initIiifViewer gets that list; showMirador() probes each image's real dimensions client-side and builds a multi-canvas inline manifest (plain image resources) so ALL objects show in one Mirador window with deep zoom + a thumbnail navigator. Objects whose file is missing on disk are filtered out server-side (resolveDiskPath) AND by the JS onerror probe, so an orphan attachment row never shows a broken canvas; _attached-carousel-tiles skips file-less tiles too. Verified on engelbrecht: object list = 2 real images (family_bible via its jpg reference + WhatsApp), orphan recto/verso excluded; reference URLs serve 200 image/jpeg; JS/views compile.
