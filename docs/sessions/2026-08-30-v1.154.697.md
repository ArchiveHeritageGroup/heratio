# v1.154.697 (2026-08-30)

fix(display): honour the 'Digital object carousel' setting - #1493. The switch on Admin -> Settings -> Default page elements has always been written by that form and read by nothing, so ticking or unticking it did nothing at all. AtoM honours the same setting - its imageflow component returns sfView::NONE on its first line when the value is falsy - so the control came across in the port and its enforcement did not. It now gates the carousel in all four sector show controllers (information object, gallery, DAM, museum) rather than in the views, so a disabled carousel also skips the queries that build the thumbnail strip instead of merely hiding the output. Two judgements are baked into the new AhgCore\\Support\\DisplayToggles helper. An ABSENT setting defaults to ON: instances installed fresh carry no toggle* rows at all, the page-elements form creates them on first submit, so treating missing as off would silently remove the carousel from every new install. An EMPTY STRING is treated as off, because that is exactly what the form writes for an unticked box, so absent and empty must not be conflated. The lookup is memoised per CONNECTION rather than in a plain static, because the test suite swaps to a different database mid-process. Verified against the real setting at four states: ticked on, unticked off, empty string off, and the row deleted entirely defaulting back on. 246 Feature tests pass.
