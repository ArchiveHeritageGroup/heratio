# v1.154.576 (2026-08-11)

fix(accession): #1463 build the rights + deaccession features the show-page buttons already promised. Reported by Stefan: 'Create new rights' and 'Deaccession' both returned 404. Both were AtoM-legacy URLs hardcoded with url() instead of route() in show.blade.php (lines 564, 578) - /right/add?slug= and /deaccession/add?accession=, neither of which has a Laravel route. The dead links were only the visible half: underneath, neither feature existed. RIGHTS: a view route did exist (accession/{id}/rights) but AccessionController::rights() hardcoded $rights = collect(), so the page reported 'No rights records' no matter what accession_rights held, and the blade was a read-only table with no create form. Now rights() actually queries accession_rights (Schema::hasTable guarded); new rightsStore() + rightsDestroy() behind accession.rights-store (acl:update) and accession.rights-destroy (acl:delete); the blade gains a create form and per-row delete and surfaces inherit_to_children, which feeds the existing accession_rights_inheritance_enabled behaviour createInformationObject() already honours, so a right captured here can flow to descriptions made from the accession. Basis and restriction validate against fixed vocabularies (RIGHTS_BASES, RIGHTS_RESTRICTIONS) rather than free text. DEACCESSION: there was no create path anywhere - the service could only READ, so the button promised something never built. New deaccessionCreate()/deaccessionStore() + accession.deaccession-create and accession.deaccession-store (acl:create), and a new deaccession-add.blade.php (identifier, date, scope, reason, extent, description, plus existing deaccessions). deaccession is a CTI table sharing its primary key with object (class_name QubitDeaccession) with no auto-increment of its own, so the object row is written first, all in a transaction; scope options come from taxonomy 66 (Whole/Part); creation is audited via AuditLog::captureCreate. The form states plainly that a deaccession documents removal and does NOT delete the accession or any description, because the button name invites that misreading. Both buttons now point at real routes and no view references the legacy URLs. Verified: rights persist and appear where the page previously always showed none; deaccession writes object+deaccession+deaccession_i18n with the right class_name; invalid rights_basis rejected, end_date before start_date rejected, unknown accession 404s; both pages 302 unauthenticated rather than 404; no unresolved Blade directives; test rows removed
