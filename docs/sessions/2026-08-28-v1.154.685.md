# v1.154.685 (2026-08-28)

fix(museum): implement the last two stubs - object comparison and the quality dashboard. Both returned hardcoded empties, found while wiring the provenance display in v1.154.684. qualityDashboard() was '$overallScore = 0; $analyzedRecords = 0;' with an 'N/A' grade, so it reported a permanent zero regardless of the catalogue - worse than showing nothing, because it asserts a measurement nobody took. It now scores museum_metadata against nine core CCO fields and reports a per-field breakdown: on dev that is 66 records at 47%, grade D, with creation place missing on 56 of them. A field counts as present on museum_metadata OR museum_metadata_i18n, because the parent carries the base value and i18n the translations, and a completeness metric that penalised translation would be actively harmful. THAT JOIN IS hasTable-GUARDED: museum_metadata_i18n is migration-created and absent from database/core/*.sql, which is what CI builds its test database from (#1471) - my first version passed locally and threw 'Base table or view not found' in the test DB, which is the same failure any instance mid-deploy would have hit. Guarded, it degrades to parent-only counting rather than 500ing. objectComparison() was '$objects = collect();' so the page rendered an empty row for every request. Nothing linked to the route, so the parameter contract was undefined; it is now ?with=slug,slug, capped at FOUR because the view divides a 12-column grid by the object count and beyond four each card is an unreadable sliver. Every object is ACL-gated INDIVIDUALLY - comparison must not become a way to read a record you could not open on its own. Verified against real data: three objects compared with title, identifier, work type and creator. 246 Feature tests pass, including two that assert the shape of a real computation rather than a fixed number, so they will not rot as the catalogue changes.
