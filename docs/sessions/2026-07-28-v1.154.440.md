# v1.154.440 (2026-07-28)

v1.154.440: fix(ingest): staged-file ingest stored masters without the /r/ path segment, so ingested images were not web-viewable.

IngestService::createDigitalObjectFromPath (the staged-path ingest the Archivematica DIP flow uses) stored the master at <heratio.uploads_path>/<ioId>/ but recorded the web path as /uploads/r/<ioId>/. heratio.uploads_path is the nginx /uploads/ alias root (no /r), and every other digital object lives under the /r/ subdir - so the file landed at uploads/<ioId>/ while the DB and the browser looked under uploads/r/<ioId>/ = broken image. Now stores under <uploads_path>/r/<ioId>/ to match the recorded path (guarded against a config already ending in /r).

Surfaced by an end-to-end test of the Archivematica -> Heratio DIP ingest: a real DIP (METS + objects/access) built from 7 png/jpg, run through DipIngestService, matched an information_object by dc:identifier and created 7 digital objects. Before: 0/7 masters resolvable at their /uploads/r/ path; after: 7/7 resolve. Verified on dev.
