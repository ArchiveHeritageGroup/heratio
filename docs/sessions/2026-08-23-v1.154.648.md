# v1.154.648 (2026-08-23)

fix(acl): the security-clearance page returned 500 on every request, and its form could never be submitted - #1478. Found by finally driving the form through a browser rather than calling the service directly, which is what the v1.154.643 verification did. THREE defects on one page, none visible to inspection or to the scanner. (1) userClearance() passed $user; the view refers to $targetUser ten times and $user never - deliberately, to distinguish the subject of the clearance from the operator viewing it - so every request raised 'Undefined variable $targetUser' and returned 500. The clearance form has never been reachable through the UI, which means the v1.154.643 fix that made it PERSIST vetting evidence was correct and unreachable. (2) The view populates its REQUIRED clearance-level select from $classifications ?? [], and the controller never passed it, so the select rendered with zero options and the form could not be submitted even once the page stopped erroring. AclService::getClassificationLevels() has existed all along; it simply was not called. (3) The form re-rendered a saved expiry from $clearance->expiry_date, but the column is expires_at - the form POSTS expiry_date and the controller maps it - so a saved expiry never came back and the field looked blank on every revisit; now read from expires_at and trimmed to Y-m-d, because it is stored as a datetime and <input type=date> rejects the time component. NOTE AN UNCOMFORTABLE INTERACTION: defect 3 was INVISIBLE to tools/scan-blade-bindings.php because the v1.154.643 fix added 'expiry_date' => 'nullable|date' to the controller's validator, which put that identifier into the package's PHP and so satisfied the scanner's deliberately-generous 'is it producible anywhere?' test. A fix in one file masked a defect in another. The heuristic's caveat on #1478 covers this, but it is the first observed instance and worth recording: adding a form-field name to a validator can hide a display binding of the same name. New tests/e2e/talk/clearance-form.spec.ts drives the real form - fills classification, expiry, all three vetting fields and notes, submits, reloads, and asserts every value survives - so the controller path, the field names and the expiry_date to expires_at mapping are now covered by something other than my reading of the code. Verified: all five fields persist and render back. 242 Feature tests pass; scan-blade-bindings --check clean.
