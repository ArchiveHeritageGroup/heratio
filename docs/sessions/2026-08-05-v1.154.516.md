# v1.154.516 (2026-08-05)

fix(#1447): detach() now removes the attached object's files from disk. attach() nulls the master's object_id so extras stay invisible to legacy reads, but DigitalObjectService::delete() resolves file paths via object_id - so detach could only delete the DB rows and left the master+derivative files orphaned under uploads_path/r/<ioId>/ (found via leftover test files). detach() now unlinks the files itself first, at the correct /r/<ioId>/ shard (path-field primary, /r/<ioId>/<name> fallback), unlinking only the specific attached files by name (the directory is shared with the record's primary object, never removed), then lets delete() do the id/parent_id-keyed DB cleanup. Verified: attach writes 3 files; detach removes all 3 + the master/derivative/link rows (0 files, 0 rows), primary object untouched.
