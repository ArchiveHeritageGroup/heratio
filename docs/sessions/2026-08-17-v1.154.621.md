# v1.154.621 (2026-08-17)

fix(privacy+forms): privacy-scan-pii ran against a column that does not exist, and Reference code autofilled with an email address. PII SCAN: the query filtered on information_object_i18n.history - there is no such column, the field is archival_history, which the same clause already checked - so every run died on 'Unknown column history'. Also --since filtered on i18n.updated_at, which is not on that table either (timestamps live on object, shared by id under CTI), so that option was latent-broken; it now joins object. And the connection defaulted to atom, denying it on any Heratio-native instance; now routed through DiscoverySource. Verified both the plain and --since paths on dev. AUTOFILL: the Reference code field on the archival edit form filled itself with johan@theahg.co.za because browsers treat an input named identifier as a username field. edit.blade.php already carried the full defence - autocomplete=off, readonly-until-focus, data-lpignore, data-1p-ignore, data-form-type - from an earlier attempt at this, but the record is edited through the dynamic per-standard form, which renders _isad-fields.blade.php, a bare input with none of it. Eleven identifier inputs across ISAD, RiC, MODS, RAD, DAM, library, research, feedback, deaccession and two advanced-search forms now carry the same treatment; the search fields get the attributes without readonly, which would fight a filter box
