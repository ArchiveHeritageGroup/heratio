# v1.154.662 (2026-08-24)

fix(nginx): shed load on heratio.org's faceted browse instead of letting it starve the pool. A user reported authority-record errors; the cause was not the application. heratio.org took 36,157 requests to /actor/browse on 2026-08-24 - 30% of the site's 120,026 - across 30,445 distinct URLs from 31,722 DISTINCT IPs, roughly one request per address, with rotating desktop-browser user agents. A distributed scraper walking the facet combinatorics (displayMode x entityType x maintainedBy x mediaType x languages x sf_culture x page x sortDir), which is an effectively infinite URL space. The visible symptom was 17 intermittent 502s on /actor/browse and 8 on /glam/browse - php-fpm not answering, which is also why every Laravel log was clean: the request died before anything could log it. That contradiction was the clue. CACHING WAS CONSIDERED AND REJECTED ON MEASUREMENT: 28,063 of the 30,445 distinct URLs were requested exactly once, so the best possible hit ratio is 9.1%. A facet space is not cacheable by construction. It would also have been risky - every anonymous response sets heratio-session and XSRF-TOKEN and embeds a session-bound CSRF token, so a naive fastcgi_cache would serve one visitor's session to everyone. PER-IP LIMITING WAS REJECTED TOO: 31,722 addresses at one request each is exactly the shape a per-IP limit cannot see. So the zone is keyed on $server_name - ONE counter for the whole vhost - capping /actor/browse and /glam/browse at 12 concurrent. The pool is pm.max_children=25 and every page costs ~1s, so 12 leaves 13 workers for the rest of the site: a burst is refused immediately rather than queueing and starving everything else. 503 rather than 429 because it is a capacity statement, not an accusation. Verified by burst: 25 concurrent browse requests gave 9 served and 16 shed, while the homepage and a help article both stayed 200 at ~0.95s DURING the burst. THE EXISTING GUARD CANNOT SEE THIS TRAFFIC, which is worth recording because it looks like it should. snippets/facet-crawl-guard.conf is already included in this vhost, but $block_facet_crawl requires BOTH a bot-shaped User-Agent AND bracket array params (AtoM's creator%5B0%5D=). This scraper sends plain Chrome, and Heratio's facets are flat - maintainedBy=, sf_culture=, displayMode=. The guard is AtoM-shaped and Heratio is not AtoM; it has been firing on none of this. deploy/nginx/heratio.org.conf is drift-checked exact against the live file, so the live edit is synced back here and the new conf.d snippet is added to the check-config-drift manifest - otherwise a rebuild would silently revert it and nothing would notice. check-config-drift reports no drift across 16 files.
