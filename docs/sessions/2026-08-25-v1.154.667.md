# v1.154.667 (2026-08-25)

feat(landing-page): resolve computed_data - six of the eight remaining #1478 findings were one absence seen from six views. Every landing-page block partial reads $data, which the page templates take from $block->computed_data, and nothing ever computed it. Statistics rendered no figures, recent items no items, the carousel no images, holdings no list and the map no locations - on every block of every landing page, for as long as the feature has existed. New BlockDataResolver turns a block's config (which entity, how many, which collection) into rows; config-only blocks like hero banner, text and spacer resolve to null and are untouched. RESOLVED FOR CHILDREN AS WELL AS PARENTS, which is the difference between fixing the finding and fixing the page: on the seeded Home page EVERY data block is a child of a row block, so resolving only the top level would have cleared all six findings and left the page exactly as empty. THE GATE IS THE POINT. The landing page is public, so every query carries the same guest gate the public browse uses - published status only for anonymous visitors, plus the #1388 community-protocol exclusion unconditionally, and actor counts through AclService::addActorVisibilityCriteria so embargoed authority records are not counted. Measured: a guest sees 297 records where an authenticated user sees 9,542. Ungated this page would have advertised 9,543 to the public, which tells a visitor how much unpublished material exists whether or not they may see any of it. A count is a disclosure, so the gate belongs on the COUNT as much as on the list, and the count cache is keyed by auth state so a guest can never be served an authenticated figure. TWO LATENT DEFECTS THE EMPTY DATA WAS HIDING. The carousel linked to route('iiif-collection.show'), which does not exist under any name - it never threw because the loop never ran. iiif-collection.view takes an {id} while config['collection_id'] holds a SLUG, so the slug-taking route is iiif.viewer, now guarded with Route::has so the page cannot 500 where ahg-iiif-collection is absent. And the map block could never render at all: machine_name is map_block while the template was _block_map.blade.php, and the templates resolve as '_block_'.machine_name - it was the only one of 21 block types with no matching template. Renamed; it now renders its honest empty state, because no repository on this instance has coordinates. Also corrected before shipping: contact_information has no city column - city lives in contact_information_i18n. 225 Feature tests pass.
