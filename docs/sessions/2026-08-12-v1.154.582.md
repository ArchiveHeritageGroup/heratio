# v1.154.582 (2026-08-12)

feat(rights): #1464 switch reads and writes to rights_record - the consolidation completes. rights_record is now the live store for object rights: every read surface and both write services move to it, with columns aliased back to the extended_rights names so the ~160 downstream references in blades, forms and controllers keep working untouched (cc_license_id -> creative_commons_license_id, copyright_holder -> rights_holder, start_date/end_date -> rights_date/expiry_date, copyright_note -> copyright_notice, rights_record_i18n.restriction_note -> usage_conditions). REPOINTED: ExtendedRightsService in ahg-information-object-manage (read, create, update, delete, snapshot), RightsHolderService in ahg-rights-holder-manage (read, TK lookup, create), both ExtendedRightsControllers, and all 7 blades with inline queries (io-manage show + rights-badge + extended-rights-context-menu, library show, museum show, dam show, core record-sidebar-extras, search rights-indicator). TWO SCHEMA ADDITIONS so the repoint loses nothing: rights_holder_uri (an authority URI the extended_rights write path carried and rights_record lacked - repointing without it would have silently dropped it) and is_primary. A SWEEP MIGRATION re-runs the v1.154.580 backfill first, so anything created in the gap between that release and this one is carried over before reads switch - that idempotency is what made the two-stage rollout safe, and this is the stage that uses it. TK/BC LABELS: the two write services both needed the legacy-to-ICIP vocabulary translation, so rather than duplicate it (the very thing #1464 exists to remove) it lives once in the new AhgCore\Services\IcipLabelAssignmentService - ahg-core already hosts ICIP-aware code in TermProtocolService and every package depends on core. Labels are OBJECT-scoped there, which surfaced a flaw in my first cut: deleting a rights record was stripping the object's labels. It no longer touches them - an object can hold several records, and a community's assertion of authority over material must not be collateral damage to deleting one rights row. ALSO FIXED IN PASSING: ahg-search/_rights-indicator selected 'creative_commons_id', a column that exists in neither the old table nor the new, so the CC indicator in search results has never once rendered. VERIFIED: full create/read/update/delete round-trip through the service (basis derived, holder URI persisted, i18n mapped, legacy TK id translated to icip tk_a, delete preserves labels - checked explicitly on an object with 3); CC licence and rights statement still render on egyptian-boat, samplearchive and engelbrecht-family-bible (samplearchive2 correctly shows none, it has no licence); all five admin rights pages 200; anonymous show pages 200 with the draft record still correctly 404ing; Unit 21/21 and Feature 231 green. extended_rights, extended_rights_i18n and extended_rights_tk_label are deliberately NOT dropped - the writers move here and the tables stay until a release has proven it in the field, same discipline as the embargo consolidation
