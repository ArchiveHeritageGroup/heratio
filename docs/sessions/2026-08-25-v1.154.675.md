# v1.154.675 (2026-08-25)

refactor(bootstrap): switch modules off per instance with a marker file, not a composer.json edit. v1.154.674 turned archaeology off on sasa by deleting its PSR-4 line from that instance's composer.json, which left the file permanently modified while the deploy runs git pull --ff-only. composer.json moved upstream 61 times in the last 300 releases - RELEASE_EXCLUDE skips it by default but is deliberately overridden whenever a new package is registered - so the next such release would have aborted sasa's deploy with 'local changes would be overwritten'. Loud rather than silent, but a broken deploy for whoever hit it first. The switch is now a marker file: touch .disabled-modules/archaeology. The directory is tracked and carries a README so it is discoverable; its contents are gitignored, so the switch is per-instance and survives every pull. Deliberately NOT env(): bootstrap/providers.php is not a config file and Laravel skips LoadEnvironmentVariables when the config is cached, so env() would return null there and the default would quietly switch the module back ON. class_exists() stays alongside it and means a different thing - off-by-choice and not-installed are separate states. harris-matrix now follows archaeology off automatically: it reads the archaeology tables and mounts its routes under /archaeology, so leaving it on over a disabled base module left a stratigraphic analyser pointed at nothing. Verified both directions on dev - no markers 30 archaeology + 4 harris routes, archaeology marker alone takes both to 0, markers removed restores 30 and 4. 231 Feature tests pass.
