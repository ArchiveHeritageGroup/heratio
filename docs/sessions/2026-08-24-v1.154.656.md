# v1.154.656 (2026-08-24)

fix(tooling): the lock manifest protected almost nothing - inline comments killed 45 of 74 entries, and bin/release disarmed the rest. Two independent faults, either one enough to gut the locks. FIRST, the manifest parser dropped comment-ONLY lines and trailing whitespace and never an INLINE comment, so an entry written as 'packages/ahg-term-taxonomy/    # term.show' became that literal string and matched no path on earth. 45 of the 74 entries were in that state, reading as locked in the manifest while protecting nothing - among them ahg-cart, ahg-loan, ahg-favorites, ahg-feedback, ahg-storage-manage, ahg-repository-manage, ahg-accession-manage, ahg-actor-manage, ahg-menu-manage, ahg-oai, ahg-annotations, ahg-portable-export, the plyr/videojs/wavesurfer vendor directories, and named files including SettingsController.php, DigitalObjectController.php and the information-object routes/web.php. BOTH parse sites are fixed together, deliberately: bin/check-locked decides whether a change is refused and bin/unlock decides whether it warns that a path is not locked, and they read the same manifest - fixing only the first would leave unlock reporting a genuinely locked path as 'not in .locked-paths - a no-op', which is the message that made this look like intended design in the first place. SECOND, bin/release cleared the one-shot unlock list AFTER git push. On heratio-dev the push always fails (origin is HTTPS and the www-data deploy key is rejected), so under set -e the script exited first and the cleanup had never run even once - the list accumulated every unlock ever issued, 158 tokens, which wholly neutralised 47 of the 74 entries and left 27 armed. The cleanup now runs immediately after the tag is created: the unlock exists to permit the commit, and at that point the commit and the tag both exist, so a failed push can no longer strand it. The stale backlog was cleared once with bin/lock --all after confirming this repo has a single worktree, no other uncommitted work, and no commits after v1.154.655 - the other session active at the time was on archaeology.theahg.co.za, a different instance on a different host, and never shared this unlock file. VERIFIED: all 74 entries parse to real paths that exist on disk, so no typos or stale entries were hiding behind the dead ones; all 74 are now armed, up from 27; a modified ahg-loan file is refused with the rule named; --staged mode refuses too, which is the path hooks/pre-commit uses; bin/unlock recognises a formerly-dead path and bin/lock removes it cleanly; and an isolated dry-run confirms the cleanup survives a failing push. EXPECT the locks to bite from here: ordinary work touching any of the 74 paths now refuses until explicitly unlocked, and each unlock is genuinely one-shot. No PHP changed, so the suite was not re-run - the 225 Feature tests from v1.154.655 stand.
