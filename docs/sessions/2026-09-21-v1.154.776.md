# v1.154.776 (2026-09-21)

fix(privacy): ahg:privacy-scan-pii wrote its findings into privacy_redaction_cache, the redacted-file cache RedactionRenderService serves from, with columns that table does not have, so no weekly scan ever stored a result (CH-000136). It also stored the matched values themselves in sample_hits, and every failed insert echoed those phone numbers, passports and emails into ahg_cron_run.output and cron_schedule.last_run_output (CH-000135). Findings now go to ahg_pii_scan_report, the ahg-privacy review queue, as record id plus a count per pattern with status pending - never the matched values, so a failed write can no longer leak them.
