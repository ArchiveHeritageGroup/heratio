# v1.154.606 (2026-08-14)

fix(acl+archivematica): blank User column in the ACL audit log, and deleted Archivematica DIPs logged as errors. ACL: the audit-log row rendered {{ $log->display_name ?? $log->user_name ?? 'Anonymous' }}, but display_name is joined from actor_i18n where an actor with no authorised form of name stores an EMPTY STRING rather than NULL - and ?? only falls through on null. So filtering by a user whose actor record has a blank name showed rows with an empty User column even though user_name was recorded correctly (louise, 221 rows). Switched to ?: which falls through on any empty value, and applied the same correction to the six other places in ahg-acl views that fell back the same way - clearances, approvers, edit-group and edit-group-profile, including the member dropdowns and a data-username attribute feeding a JS confirm prompt. Archivematica: a package the Storage Service has DELETED still answers its metadata endpoint but returns an opaque HTTP 500 with 'this request could not be processed' when asked to download, so three deleted DIPs logged a Storage Service error on every sweep. DipIngestService now reads the package status first and skips anything not UPLOADED with a clear reason, alongside the existing already-linked skip; unreachable metadata still falls through to the download so a genuine Storage Service fault is not masked
