# v1.154.583 (2026-08-12)

feat(icip): #1464 BC Consent Before restricts, and the community-protocol gate now covers the show pages it was missing. Johan's decision on the label deferred in v1.154.581: BC Consent Before is a consent-required label and now carries default_access_condition='restricted', one of TermProtocolService::RESTRICTED. Shipped as a migration so every instance picks it up, and it only changes the value the TK migration seeded ('attribution') - an operator who has since chosen something else deliberately keeps it. THIS TIGHTENS ACCESS: material becomes less visible, never more, which is the safe direction for a consent label. Affected at time of writing: 4 objects on dev (1 published), 3 on heratio.org (2 published - Egyptian Boat and Understream Figure), 0 on sasa. ENFORCEMENT GAP CLOSED, and this is the substantive half. TermProtocolGate was already enforced on browse, display, exports, OAI, RiC, GraphQL and the metadata-export commands, but NOT on any record show page: those guard ICIP through IcipAccessService, which reads cultural notices rather than TK-label-derived protocol conditions. So a restricted record vanished from every listing while its direct URL still served - protected everywhere except the one place a bookmark reaches, which is worse than no protection because it looks protected. Added TermProtocolGate::allowsRecord() to all FIVE sector show controllers: InformationObjectController, DamController, MuseumController, LibraryController and GalleryController. Gallery was the one that mattered most and was easiest to miss - the archival show page 302-redirects gallery records to /gallery/{slug}, so gating only the first would have left the redirect target wide open, and Understream Figure is exactly such a record and is PUBLISHED on prod. 404 rather than 403, matching the gate's behaviour elsewhere and the adjacent draft gate: a restricted record is not confirmed to exist. Placed AFTER the existing ICIP check in InformationObjectController so that check still audits the view to icip_access_log for every viewer first. allowsRecord() bypasses staff internally, so editors and admins are unaffected. VERIFIED: guests 404 on both /understream-figure and /gallery/understream-figure while an unlabelled published record still serves 200, proven by temporarily publishing the record on dev to reproduce the prod state exactly and then restoring it to Draft; staff still see restricted records; Unit 21/21 and Feature 231 green
