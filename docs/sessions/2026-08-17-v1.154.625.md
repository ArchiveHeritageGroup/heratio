# v1.154.625 (2026-08-17)

feat(schema): #1470 harden status.id - drop AUTO_INCREMENT + add the missing CTI foreign key, and fix 3 more id-less insert paths the earlier sweep missed. status was the only one of object's 24 CTI children with no FK on id and an auto-increment counter of its own, which is why id-less inserts silently took numbers from the wrong id space for months (417 orphans on heratio.org, 9,621 misplaced on dev, ending in a user-facing 'Duplicate entry 914261 for key status.PRIMARY' 500 on the edit form). Two migrations: 130000 drops the AUTO_INCREMENT (guarded - skips unless every row already sits on its own QubitStatus object), 140000 adds FOREIGN KEY (id) REFERENCES object(id) ON DELETE CASCADE to match all 24 siblings. Dropping it immediately exposed 3 paths a 12-line-lookahead grep had wrongly cleared: InformationObjectApiController V1 POST /api/records, ImportJob, and InformationObjectFactory - all now via StatusRow, plus the DraftRecordVisibility fixture. Verified: omitted id rejected, non-object id rejected by the FK, StatusRow set/put/ensure work, cascade works, real HTTP create+edit-save both 302 with the status row on its own QubitStatus object, 9,906 rows intact, 231 Feature tests pass. Fresh-install path proven by rebuilding heratio_test from core SQL + seeds and running the chain (1,139 rows rehomed then hardened); core schema keeps its AUTO_INCREMENT deliberately for the July actor-embargo migration, now documented in place
