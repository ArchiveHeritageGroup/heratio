# v1.154.707 (2026-09-01)

fix(archaeology): the stratigraphic loop guard now reasons over merged nodes, closing #1499 and a second hole it did not know about. The guard refused any DIRECTIONAL edge that would make a context later than itself, but it tested raw context ids against a graph the matrix does not actually use. The matrix merges same_as contexts into one node before it draws anything, and the guard did not. TWO CASES GOT THROUGH, both reproduced on real data before the fix and both refused after it. First, the one #1499 was filed for: same_as was skipped entirely because it has no direction of its own, so "D above E" followed by "E same_as D" was accepted - merging two contexts that are already ordered closes a loop just as surely as a backwards above does. Second, and NOT in the issue: a directional edge was also tested on raw ids, so "A same_as B" plus "B above C" plus "C above A" was accepted, because A alone reaches nothing while the node {A,B} it belongs to is above C. addRelationship now applies the same same_as union-find the matrix builder applies, then asks whether the affected NODE can reach itself. The subtle part is a self-edge: when the proposed same_as merges two contexts, an existing later-than edge between them collapses to a node pointing at itself, and discarding that as a degenerate self-edge is exactly what hid case one - my first attempt did precisely that and still let it through, which is why it is now handled explicitly rather than skipped. bonds_with and abuts are deliberately never refused: they assert physical contact rather than identity, so the builder neither unions them nor draws a later-than edge for them, and they cannot order anything. Verified rather than assumed by reading harrisMatrix(), which unions same_as alone. The decision is extracted as a pure static, ArchaeologyService::closesLoop(), for the same reason reduceTransitively() is - the archaeology tables are migration-created and CI builds its test database from database/core/*.sql alone (#1471), so a DB-backed test would skip in CI and prove nothing. 10 new tests cover both missed cases, the cases that always worked, and the four legitimate relationships that must still be accepted. 256 Feature tests pass, up from 246. The user guide no longer documents this as a known gap, and explains instead why the consistency report still checks for loops: the form is not the only way data reaches the database, and the demo teaching site carries a loop recorded before this guard covered it.
