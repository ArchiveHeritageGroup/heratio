# v1.154.610 (2026-08-14)

feat(audit): capture before/after on user and term edits, and stop losing the diff outside HTTP. The audit-log modal has always rendered a Field/Before/After table and AuditLog::captureEdit has always produced that shape, but only some edit paths called it - user edits (7 rows on prod, 0 with a diff) and term edits recorded a path and nothing else, so a reviewer could see that a record changed but never what changed. UserService::update and TermService::update now snapshot before the transaction and captureEdit after it, so a rolled-back edit records nothing; the user snapshot deliberately excludes the password hash, since a diff is for seeing what changed and not for copying a credential into a second table. Found while verifying: AuditLog::stash sets request attributes for the AuditLog middleware to flush and fell back to writeDirect only when app('request') THROWS - which it does not do in console or queue context, where Laravel supplies a synthetic request. So every edit made by an artisan command, a queued job or a seeder stashed its diff onto a request nobody read and silently lost it. stash now writes straight through when runningInConsole. Verified end to end: a user email edit records changed=[email] with correct before and after, likewise a term rename, and both probe records were restored to their original values
