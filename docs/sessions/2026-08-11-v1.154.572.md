# v1.154.572 (2026-08-11)

fix(core,io): incremental reindex + create-form publication status. (1) ahg:search-update --since has never worked for any type: it filtered <table>.updated_at, but information_object/actor/term/repository are all QubitObject subclasses with no timestamp columns of their own - every run died with 'Unknown column updated_at in where clause', so incremental ES reindexing silently never ran. Now joins object and filters object.updated_at; also passes --no-progress to the ahg:es-reindex delegate, which was drawing a progress bar per record inside a loop. Verified: default 24h window, explicit --since, --type=actor (368 records), unknown-type warning. (2) InformationObjectController::store() wrote no status row at all, so every description created from the form landed with no publication status - neither Draft nor Published, just absent - which reads as unpublished to guests (404) and matches neither value in a publication-status filter; create.blade.php offers a Draft/Published select whose value store() never read, so the operator's choice was discarded and the defaultPubStatus global was ignored on this path. store() now writes status using the same resolution as InformationObjectService::create() (explicit publication_status_id > defaultPubStatus global > Draft) with an allow-list so an out-of-range value falls back to Draft. Visibility-neutral by default (defaultPubStatus=159)
