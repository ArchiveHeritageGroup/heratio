# v1.154.692 (2026-08-29)

docs(api): mark API-COMPARISON.md historical - it told integrators Heratio has no write API. The document was a gap analysis written 2026-03-17, when the API really was 18 read-only v1 endpoints with no key management, and its 'What Heratio HAS' and 'What's MISSING' sections still describe that. The backlog it lists has since been delivered: routes/api.php now carries 212 routes - 150 GET, 34 POST, 17 DELETE, 10 PUT, 1 PATCH - with working key management at GET/POST /api/v2/keys and live keys in ahg_api_key. Wrong by an order of magnitude, and wrong in the direction that costs us: someone evaluating an integration reads it, concludes there is no write API, and goes to build something else. Raised by the bookings session while assessing whether that platform could push records into a Heratio instance, which is exactly the reader this document misleads. The header now marks it superseded and points at api-user-guide.md for the current API. It also states plainly that authentication is NOT OAuth 2.0 - there is no Passport and no Sanctum in the codebase - because KM has been answering that question with a confident OAuth token-endpoint flow that does not exist. The real scheme is a bespoke key: X-API-Key (or X-REST-API-Key, or Authorization: Bearer), Str::random(48) stored sha256-hashed in ahg_api_key with scopes, rate limit and expiry, in ApiAuthenticate.php. Kept rather than deleted because the priority ordering records why the API was built in the sequence it was.
