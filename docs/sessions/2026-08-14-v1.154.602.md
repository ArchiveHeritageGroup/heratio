# v1.154.602 (2026-08-14)

fix(cron): five more scheduled commands that had never worked, all failing every run. ahg:workflow-process used claim_at, started_at and due_at - the real columns are claimed_at and due_date - so it died on 'Unknown column claim_at' and had never claimed a task; its seeded schedule also passed --notifications, an option the command does not define and whose behaviour it does not implement, so the seed drops it and the description no longer claims it sends email. ahg:workflow-sla-check joined p.queue to t.queue when both key on queue_id, compared p.sla_hours when the policy stores due_days, and flagged breaches on sla_breach/sla_breach_at which are not columns on ahg_workflow_task; the query is rewritten against the real schema, --queue now resolves a queue name or slug through ahg_workflow_queue, and a migration adds the two missing columns so a breach has somewhere to record. ahg:triposr-health and ahg:ai-condition-status both returned FAILURE for integrations that are merely switched off or documented as unwired (#1268) - 331 and 320 logged failures on sasa alone - and now report and exit 0, reserving non-zero for an enabled integration that cannot be reached. TriposrHealthCommand and TriposrPreloadCommand both imported AhgSettingsService from AhgSettings\Services when it lives in AhgCore\Services, so they fataled before reading a setting. Config, not code: sasa had no discovery_db_connection so it fell back to the 'atom' default and was denied access to a database it does not own; set to its own connection
