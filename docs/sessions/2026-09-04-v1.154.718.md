# v1.154.718 (2026-09-04)

fix(privacy,spectrum): one reader for the jurisdiction registry, closing #1507 - and the fifth copy was picking an arbitrary row. The issue named three inline copies of the registry query in PrivacyController; fixing those made two more obvious, and one was not duplication but a defect. SpectrumController::privacyCompliance() resolved its active jurisdiction with where(is_active, 1)->first(), no code filter and no ordering, so it returned whichever active row MySQL happened to yield - not the operator's selection, and not necessarily the same row between two loads of the same page, so the header naming the regime could disagree with the figures underneath it. PrivacyService::activeJurisdiction(code) now answers it: the named code when the registry carries it, the first by sort_order otherwise, null when there is nothing. It returns an object because the dashboard and Spectrum views read name, full_name and country off it as one, and an object built from activeJurisdictions() rather than the raw row, so callers depend on this service's shape and not on the columns. All five sites now read it: dashboard(), config(), officerList(), jurisdictionOptions() and privacyCompliance(). officerList() gains a fallback it never had - an install with no registry table used to render an empty jurisdiction list there - and config() loses its own duplicate copy of the popia and gdpr fallback pair. jurisdictionOptions() keeps its catch, because it is called from contexts with no database at all, and that path is verified to still return the minimal pair. ONE INLINE READ IS DELIBERATELY LEFT: DataProtectionSettings looks up dsar_days by code WITHOUT the is_active filter, which is right - an in-flight DSAR under a regime the institution has since switched off still has its deadline - and routing it through the shared reader would silently break that. It carries no comment saying so, which is why it is said here. Six tests pin the selection contract the callers now depend on, including that ordering comes from sort_order rather than from whatever the database returns first, which is the Spectrum defect stated as an assertion. They seed their own rows and deactivate the rest first: the test database ships its own registry, and a test that assumes an empty table is exactly what kept the Package suite red for five weeks. 1058 Package tests pass, up from 1052, and 286 Feature tests pass.
