# v1.154.683 (2026-08-27)

fix(auth): CLI password commands wrote a hash the login could never verify

ResetPasswordCommand and AddSuperuserCommand wrote sha1(salt . password) directly,
but AtomUserProvider validates with password_verify(sha1(salt . plaintext), password_hash).
password_verify against a raw SHA-1 never returns true, so every account reset or
created through the CLI was locked out permanently - silent at write time, and
reported at login as credentials not matching.

Both now call LoginController::hashPassword(), which is the single definition of the
scheme. Three copies existed and two had drifted.
