# v1.154.703 (2026-08-31)

feat(label): storage container labels with a QR that resolves to what is in the box. The last of the QR surfaces, and the only one that could not simply be added: ahg-label had no notion of physical_object at all, so there was no container label to put a code on - and no page for a code to lead to. A QR is only worth printing if scanning it answers the question the person holding the box actually has, so this adds the missing destination first: /admin/storage/container/{id} lists a container's name, type, location and its holdings, resolved through the has-Physical-Object relation. Holdings are ACL-filtered per record rather than merely listed, because a box label must not become a way to enumerate records the viewer could not open directly. /admin/storage/containers lists every container with a holdings count - an empty box is either a mistake or one waiting to be filled, and both are worth seeing at a glance - and selected containers print as a label sheet whose QR points at that container's page, rendered locally so a store room with no network can still print. Two placement traps found by testing rather than reasoning. nginx denies ^/storage/ on every instance because that is Laravel's own storage directory, so the obvious /storage/containers 403s before it ever reaches PHP; weakening that rule fleet-wide to gain a route would have been the wrong trade. And a single-segment /containers would have been swallowed by the /{slug} record catch-all, whose exclusion list lives in a locked path. Both avoided by living under /admin/storage/, which is also where a staff-only store-room tool belongs. Verified on dev, which has no containers at all: the list returns 200 with a clean empty state rather than an error, and the routes redirect an anonymous visitor to login. The demo's six containers are the real test and follow at deploy. 246 Feature tests pass.
