# v1.154.681 (2026-08-26)

fix(release): signal the local queue workers on release, so dev stops serving jobs from stale code. heratio-dev is a release SOURCE, not a deploy target - heratio-deploy.sh restarts the workers on heratio and sasa, but nothing ever restarted the ones here. A queue:work process loads the application ONCE and serves every subsequent job from that copy, so dev's worker went on running whatever code was current when it last started: found at 1 day 17 hours old on 2026-08-26, serving jobs from a release two days stale, which makes dev useless for testing anything queued and does it silently - there is no error, the jobs just run yesterday's logic. Caught only by reading process ages after shipping the queued research fetch in v1.154.680, which that worker could not have executed at all since the class did not exist in the code it held. Uses artisan queue:restart rather than systemctl: it needs no root (this script runs as www-data), it lets a worker finish the job in hand instead of killing it mid-flight, and the unit is Restart=always with RestartSec=10s so systemd brings it straight back - verified, the worker cycled within seconds. Placed ABOVE git push for the same reason the unlock cleanup is: dev's push always fails and set -e would exit before this ever ran, which is exactly how the UNLOCKED cleanup went unexecuted for 158 accumulated tokens. Guarded on the presence of artisan so the step is a no-op anywhere the script is run outside an app root.
