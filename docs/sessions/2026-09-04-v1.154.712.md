# v1.154.712 (2026-09-04)

fix(privacy,tests): seed every jurisdiction the product advertises, and make the tests that were meant to catch this actually run. JURISDICTION SEED: privacy_jurisdiction decides what an operator can SELECT, because jurisdictionOptions() reads it with is_active = 1; it does not decide what the scanner can detect. install.sql seeded five regimes, two of them inactive, so a fresh install offered three - while the privacy dashboard and the Spectrum compliance page have always listed six and the complaint form four. The disagreement ran both ways: uk_gdpr is seeded and appears in no menu at all. ndpa and kenya_dpa existed only in the heratio-dev database, added there by hand, which is exactly why this survived - on the one instance anyone tested the registry looked right, so a fresh install advertised Nigeria and Kenya, both named target markets, and offered neither. v1.154.710 argued its jurisdiction fix from that dev registry without noticing the seed did not match it. Seven rows now, all active, ordered as dev already orders them. Metadata for the two new rows is taken from the definitions already in SpectrumController rather than from anywhere new, with regulator abbreviations expanded to this file's style. ON DUPLICATE KEY UPDATE still touches name alone, deliberately: refreshing is_active would silently re-enable a regime an operator had switched off, on every deploy. Validated structurally, 13 columns against 13 values per row, not executed - the DB rule forbids an unrequested INSERT. A new pure-file test parses the seed and the dashboard menu and asserts every advertised code is seeded active, proven by deleting the ndpa row and watching it fail; it also fails loudly if either file stops parsing, rather than passing vacuously. AHG-PRIVACY TESTS RAN NOWHERE: the 43 pure-logic privacy tests, including the 26 written at v1.154.710, are picked up only by the All suite glob, and CI does not run All. They passed the whole time, which is why nobody noticed they protected nothing. Now in the Package suite. PACKAGE SUITE WAS RED FOR FIVE WEEKS, two independent stale-test causes, neither a product defect. RequireAdmin sent a logged-out visitor a bare 403 until v1.154.451 changed it to a redirect to login, matching the auth middleware; an authenticated non-admin still gets 403. Twenty-four smoke tests across eight classes asserted the old 403 literally in three different shapes. They now share one assertAdminGated helper on the base TestCase, which accepts a 302 only when it points at login, because accepting any redirect would let a route that quietly stopped being admin-gated pass, and that is the one thing these tests exist to catch. Proven by pointing a test at a public route and confirming it fails. Separately, v1.154.610 correctly switched AuditLog::stash on runningInConsole rather than on whether a request is bound, since Laravel hands console and queue code a synthetic request and every artisan, job and seeder edit was setting attributes nobody read. PHPUnit is always console, so two vendor tests reading the request stash could no longer see it. Nothing was lost, it moved: they now assert the persisted security_audit_log row, which is what an auditor reads, with the redaction assertions unchanged. 390 Package tests pass, up from 347 with 26 failures, and 286 Feature tests pass.
