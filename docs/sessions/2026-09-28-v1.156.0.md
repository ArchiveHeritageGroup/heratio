# v1.156.0 (2026-09-28)

feat(storage): storage movement log - where holdings have been,
  and where they are now (heratio#1514, atom-ahg-plugins#193). Port of the AtoM ahgStorageManagePlugin movement log on the same tables, copied verbatim so both platforms read one schema: 
  ahg_storage_movement is an append-only record, one row per move per subject, and ahg_physical_object_location is the current-state index written in the same transaction, the same split as parent_id
  and its closure. A NULL side is load-bearing and reads per subject - for an object a first placement or removal from storage, for a location its old and new parent with NULL the root - so the foreign
  keys are RESTRICT, and name snapshots keep rows readable after a rename or a deleted account. StorageMovementService covers single and bulk moves (one transaction, shared batch_id, skipping objects
  already at the destination); a location reparent logs exactly one event inside the same transaction; deleting a location is refused while it holds objects or appears in the log. UI: movement history
  and an objects-here card with bulk move on the location page, current location and history plus a Move action on the object page, and a move form. The provider guard now checks the movement t[Hable too or existing v1.155.x installs would never get it. New StorageMovementTest carries the invariants from the plugin's storage-movement-check.php, first among them that the index always equals the latest
  movement per object; 8 tests, package 27/27.
