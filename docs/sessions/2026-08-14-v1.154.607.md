# v1.154.607 (2026-08-14)

feat(acl): align and humanise the audit-log Action filter. The Action dropdown was built with SELECT DISTINCT action from that instance's own rows, so dev offered thirteen actions and heratio.org nine - the same screen behaving differently depending on where it was opened, and an action being unfilterable until somebody happened to perform it. New AhgCore\Support\AuditActionLabels holds the canonical code=>label catalogue (28 actions across record lifecycle, digital objects, description/publication and access/identity); the dropdown now renders that, unioned with any code present in the data that the catalogue does not know yet so nothing becomes unreachable. Raw codes are also humanised in the Action column - digital_object_attach reads 'Digital object attached', publication_status_change reads 'Publication status changed' - with the raw code kept as the badge title and an unknown code humanised generically rather than hidden. Also fix(archivematica): verified the deleted-DIP skip from v1.154.606 now takes effect; it was correct in code but IngestDipFromSs is a queued job and the queue workers had been running for nearly nine days, executing pre-fix code. Workers restarted on all three instances via queue:restart
