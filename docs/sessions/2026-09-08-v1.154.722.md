# v1.154.722 (2026-09-08)

fix(ric,media): the three errors standing open on heratio.org, two of which were the log lying about the cause. RIC LABELS: extractLabel() built a $cultures list and walked it correctly in three branches, then three closures in the event and instantiation branches closed over $culture - singular, and never assigned anywhere in the method. Six uses, zero assignments, so both branches threw Undefined variable $culture on every call; prod logged only the instantiation one because that is the branch its traffic reached. An incomplete refactor from a single culture to a preference list. The event row and the digital_object row are not culture-dependent in the first place - only their labels are - so both now fetch the row once and resolve labels with the same $cultures walk the other branches use, which is one join fewer as well as correct. Exercised against real data: instantiation, event and production URIs all return labels, and a missing id falls through to the generic rule rather than throwing. DERIVATIVES: regenerateDerivatives() shelled out to ImageMagick for every master with a row, whatever it was, and logged two ERRORs per failure. 24 files, 164 error lines in one day, and almost certainly what exited ahg:cron-run non-zero 69 times - the scheduler reports only that the command failed, and the cause sits in a log nobody reads because it is full of these. A .csv has no thumbnail; that is a fact about CSVs, not a failure, and recording it as one is how an error log stops being read. Now guarded on format, with the stored mime type overriding the extension so a .jpg whose mime says audio is not attempted. THE LOG WAS ALSO MISLEADING ABOUT THE REST: three of the four real images reported Not a JPEG file: starts with 0x41 0x48 and bad magic number 18497 - and 0x41 0x48 is AH, the opening of the AHG-ENC-V2 envelope. Those files are intact and encrypted, not corrupt. isFileEncrypted() detects only Heratio's own AHG_ENC_DERIV_v1 envelope, which it can decrypt; the foreign V2 envelope exists in EncryptionService for DETECTION ONLY and nothing here decrypts it, so those masters fell through to ImageMagick as ciphertext. They are now skipped with a reason that says so, because the honest response to Not a JPEG file is to re-ingest or delete a perfectly good master. webp was checked rather than assumed and stays supported - this ImageMagick reports WEBP rw+ libwebp 1.3.2, and the webp that failed was ciphertext wearing a .webp name; dropping it on that evidence would have silently stopped thumbnailing every genuine webp in the estate. Of the 24 files, 20 skip on format, 3 on ciphertext, and exactly 1 still errors - a TIFF with genuine MM* magic that crashes ImageMagick's allocator outright, which is a real failure and should stay visible. 19 tests, and the Package suite passes 1110, up from 1091, with 286 Feature.
