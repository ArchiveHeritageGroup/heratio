# v1.154.489 (2026-08-03)

feat(archaeology): #1428 Phase 4b - spatial indexing so recorded sites are mappable. Archaeology sites/finds/contexts already extend information_object, so they were already text-searchable in ES; the gap was purely spatial - the IO geo_point (gis) loads only from ric_place (place access points), never from a site's own archaeology_site.latitude/longitude, so recorded excavation coordinates never mapped. EsReindexCommand::reindexInformationobject geo-load now also pulls archaeology_site lat/long by information_object_id (Schema::hasTable guarded), filling the IO geo_point when no place-derived coordinate exists; non-archaeology IOs are untouched. Verified: the RFS-2026 site IO now carries gis_lat/gis_lng + the combined gis geo_point from its own coordinates. Per-instance deploy: ahg:es-reindex --index=informationobject to pick up existing site coordinates.
