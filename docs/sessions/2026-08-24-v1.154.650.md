# v1.154.650 (2026-08-24)

feat(library): finish the branch axis - notices, hold routing, and a loan-rule editor that never existed - #1473. A FOURTH COPY OF THE LOAN-RULE LOOKUP was hiding in LibraryOverdueNoticeService, and it ignored the branch axis entirely - so an overdue notice quoted the system-wide fine rate even where the lending branch had its own rule, and told the patron they owed the wrong amount. v1.154.634 consolidated three copies of that query; this is the one it missed. All four now go through one public LibraryCirculationService::ruleFor(). Notices also carry the branch: the query selects the checkout's branch (falling back to the copy's, guarded on hasColumn so an instance mid-deploy still sends), and a {{branch_name}} token resolves it - falling back to the library name so a template that has never heard of branches still reads correctly. HOLD ROUTING now distinguishes two things that were conflated. The queue CAP stays service-wide, because a consortium must not be able to exceed it by spreading holds across branches. The queue POSITION is per pickup branch: a patron collecting at branch B is not behind the people waiting at branch A, they are waiting for a copy routed to B, and numbering them globally told them they were third in a queue they were not in. Verified: two holds at A get 1 and 2, B's first patron gets 1 rather than 3. promoteNextHold() also takes the branch a copy came back to and satisfies that branch's queue first, falling through to the service-wide queue only when nobody is waiting there - which is what routing a hold to a pickup point actually means. Verified: a copy returned at 982 promoted the hold at 982. THE LOAN-RULE EDITOR: library_loan_rule had NO create, update or delete anywhere in the codebase - one read-only list was the entire surface, so the table that decides every loan period and fine rate could only be changed in SQL or not at all. Added saveLoanRule()/deleteLoanRule(), routes behind acl:update and acl:delete, an editor form with the branch selector, and per-row delete. Keyed on (branch_id, material_type, patron_type), which is the table's own unique constraint, so saving the same combination edits the rule instead of failing on a duplicate key - verified, along with delete. PATRON BROWSE scoped to the operator's branch. A patron with NO home branch stays visible at every branch: they belong to the service, and hiding them would lose them. array_key_exists rather than !empty on the filter, because a branch_id of null is a meaningful 'every branch' and must not be read as 'filter not supplied'. 443 tests pass (245 Feature + 198 ahg-library), including three new cases pinning per-branch queue position, branch-local promotion, and edit-in-place rule saving. STILL OPEN on #1473, deliberately: an administrator override forcing a staffer to one branch - today any operator may select any branch, which suits a public-library service and not a consortium with contractual separation - and dropping the legacy free-text library_copy.branch / library_hold.pickup_branch columns, which should wait until an operator has reconciled whatever the backfill could not match.
