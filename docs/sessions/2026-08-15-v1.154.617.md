# v1.154.617 (2026-08-15)

fix(cron): museum-exhibition ran against columns that do not exist, and managed schedules could collide with themselves. museum-exhibition queried start_date/end_date and wrote opened_at/closed_at - the exhibition table has none of those; the real columns are opening_date, closing_date and actual_closing_date - so it threw 'Unknown column start_date' on every run. It also matched only status='scheduled', a value that appears in the code's vocabulary but in none of the data (records here carry 'preparation'), so even with the right columns nothing would ever have transitioned; the pre-opening set now covers scheduled, planning and preparation. Separately, managed cron entries were registered with ->name() and ->onOneServer() but never ->withoutOverlapping() - only the missed-run detector had it - so a job that overran its interval collided with its own previous run. refresh-facet-cache rebuilds ~558k rows hourly and died on 'Lock wait timeout exceeded' five times in one day on heratio.org. All managed entries now carry withoutOverlapping(120); the explicit expiry matters because the default lock never expires, so a worker killed mid-run would block its job for ever
