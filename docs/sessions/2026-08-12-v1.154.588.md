# v1.154.588 (2026-08-12)

fix(deploy): #1465 check-config-drift reported UNREADABLE files as drift - a false positive on every unprivileged run. Shipped in v1.154.587 and caught immediately by running it on prod as www-data: /usr/local/sbin/*.sh is mode 0750 root, so an unprivileged run cannot read them, diff fails, and all three sbin scripts were reported as DRIFT when they were byte-identical. I had only ever run the check as root, which is exactly the blind spot it was written to close. Unreadable is now its own outcome - reported in yellow with 'run as root to compare', counted separately, and it does NOT fail the check. That distinction matters more than it looks: a check that cries wolf on every cron run is a check people learn to ignore, which is worse than having none, and this one would have been wrong every single time it ran as www-data. Verified at BOTH privilege levels this time: as root 13 compared / no drift / exit 0; as www-data 10 compared + 3 unreadable / no drift / exit 0; and a deliberately injected change to deploy/cron/heratio-schedule is still detected as real DRIFT with exit 1 while running unprivileged, so the softened handling has not blunted it
