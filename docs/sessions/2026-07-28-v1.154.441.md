# v1.154.441 (2026-07-28)

v1.154.441: fix(archivematica): transfer staging built a doubled /uploads/uploads/ path, so no files were staged for AM transfers.

TransferService::stageFiles resolved a digital object's on-disk path as <heratio.uploads_path>/<digital_object.path>, but digital_object.path already includes the /uploads/ web prefix (/uploads/r/<io>/...). Since heratio.uploads_path ends in .../uploads, the result was .../uploads/uploads/r/<io>/... - which never exists - so staging found 0 files and every Heratio->Archivematica transfer failed with 'No digital-object files found on disk to stage'. Now strips the /uploads/ prefix before joining to uploads_path (matching the nginx /uploads/ alias). Companion to the v1.154.440 ingest /r/ fix.

Found running the full Archivematica round-trip against the AM VM (192.168.0.150): after this fix Heratio successfully staged 7 images, started + approved the transfer on the AM dashboard, and obtained a transfer UUID. The transfer then failed inside Archivematica at the 'Assign UUIDs to directories' microservice - a VM-side issue, not Heratio.
