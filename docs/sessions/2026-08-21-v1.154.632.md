# v1.154.632 (2026-08-21)

fix(ner): adopt orphan NER entities so the ledger reconciles on every instance - #1472 follow-up. v1.154.631's backfill attributes each extraction row its own entities via ahg_ner_entity.extraction_id, which reconciled exactly on dev but NOT on heratio.org: 2,123 entities stored against 2,108 accounted for, and 61 objects holding entities against the 47 the privacy statistics counted. The difference is 15 entities with extraction_id IS NULL - written by a path that saved entities without ever opening a ledger row, so the backfill had nothing to attribute them to (14 objects, all scanned 2026-08-14; dev and sasa have none). Leaving them stranded would leave the POPIA surface still under-reporting the objects that contain detected entities, which is the point of the issue. This reconstructs one ledger row per (object_id, day the entities were created) - entities written together on one day for one object are one scan - taking extracted_at from MIN(created_at) of the entities themselves and entity_count from how many are adopted, status completed because the entities exist so the scan plainly finished. The entities are then linked to the new row, so the ledger STAYS reconciled if the backfill is ever re-run rather than orphaning them again. Nothing is invented beyond the grouping, which is derived from the evidence. Idempotent: a second run finds no null extraction_id. Verified as a clean no-op on dev (ledger 2,108 = 2,108 stored, unchanged) and the migration logs a warning if the ledger still fails to reconcile after it runs. 231 Feature tests pass
