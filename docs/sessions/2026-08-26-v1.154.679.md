# v1.154.679 (2026-08-26)

feat(research): fetch documents from external sources into a workspace, and bound the upload box - #1492. The research pack could RECORD where a source lived - InboxService stores source_url as a string - but nothing ever retrieved it, so a researcher could bookmark a document and not bring it in. ResearchSourceFetchService now pulls it into the workspace with provenance: source URL, fetch timestamp, sha256 and the mime type SNIFFED FROM THE BYTES rather than trusted from the header. This is server-side fetching of a user-supplied URL - the textbook SSRF shape - so every request goes through the existing AhgCore SsrfGuard rather than a third hand-rolled guard, and redirects are followed one hop at a time with the guard re-asserted on each, because SsrfGuard::safeHttpOptions disables curl's own redirect following precisely so a 30x to 127.0.0.1 cannot walk past a check that already passed. Verified blocked: loopback, private LAN, localhost by name, cloud metadata, integer-encoded 127.0.0.1, and non-http schemes - six regression tests pin them. The size cap is enforced DURING the transfer via CURLOPT_WRITEFUNCTION, not from Content-Length, which is a claim rather than a fact; verified by capping at 1 MB and fetching a larger document, which aborted with no partial file and no database row. THE UPLOAD BOX had no per-file limit at all - validation was 'required|file', leaving PHP's upload_max_filesize as the ceiling, which is 2 GB on the heratio and sasa pools. The storage quota is a TOTAL checked after the file is already written, so it absorbs an oversized upload and complains afterwards, and a researcher with no policy row resolves to unlimited. Now bounded by one configurable limit resolved in ResearchQuotaService and shown in the form. Upload and fetch ceilings are deliberately SEPARATE methods: upload_max_filesize governs multipart uploads and is meaningless for an outbound GET, and a queued fetch runs under the CLI SAPI where clamping would have cut 100 MB to 2 MB on this host. Migration mirrored into database/core per #1471 and the column read is hasColumn-guarded. 237 Feature tests pass.
