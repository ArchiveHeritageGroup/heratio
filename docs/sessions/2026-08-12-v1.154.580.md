# v1.154.580 (2026-08-12)

feat(rights): #1464 backfill rights_record from extended_rights + legacy rights (target model made real; reads NOT yet switched). rights_record is the decided authoritative model - a strict superset covering all five PREMIS bases (copyright, licence, statute, donor, policy) with a direct object_id and a complete CRUD service - but it had never held a row. This populates it. The two sources are COMPLEMENTARY, not duplicates, and 5 of 7 objects appear in both: extended_rights carries rights statement + CC licence + holder, while legacy AtoM rights carries basis + copyright status and attaches through the relation table rather than an object_id. So the migration writes ONE rights_record per object, merging both - producing two records per object would misrepresent a single right as two. Basis is resolved from the rights-basis taxonomy (term 170 Copyright, 218 Donor) and falls back to 'license' when a CC licence is set with no legacy assertion, else 'copyright', matching what saveRightsRecord() assumes. Result on dev: all 7 objects backfilled with correct bases (copyright/license/donor), copyright_status resolved from taxonomy 69 (Under copyright / Public domain), i18n carried across (rights_note, and usage_conditions -> restriction_note). DATA-WIDTH FIX found by running it: rights_record.copyright_jurisdiction is varchar(10) - an ISO code - where legacy rights.copyright_jurisdiction is varchar(1024) free text; one row held 'Copyright Jurisdiction' and blew the insert. Truncating would leave a meaningless fragment and widening would undo the target column's design, so a value that plausibly IS a code is carried and anything longer is preserved as prose in copyright_note. NON-DESTRUCTIVE: nothing deleted, no read surface changed, extended_rights remains the display source. Verified idempotent - re-running leaves the count unchanged - and re-running also picks up stragglers, tested by creating an extended_rights row post-backfill and re-running. KNOWN GAP, stated deliberately: the UI still writes extended_rights, so the two stores can drift until the read/write repoint lands (40 sites across 12 files, 7 of them blades with mismatched column names - creative_commons_license_id vs cc_license_id - and two incompatible i18n shapes, touching every record show page). That repoint must re-run this backfill first to sweep up anything created in the gap; the idempotency above is what makes that safe. Legacy rights rows with no relation row cannot be placed against an object and are left alone, logged. Unit 21/21 and Feature 231 green; show pages unaffected
