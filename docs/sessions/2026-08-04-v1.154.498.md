# v1.154.498 (2026-08-04)

feat(icip): #1427 - enforce all ten graded-access restriction types (fail-closed + steward affiliation). Per the product decision (Johan): FAIL CLOSED on an unknown user attribute, and reuse the existing icip_community_steward link as community affiliation. IcipController::checkAccess() now evaluates every type: community_permission_required allows a STEWARD of the restricting community and denies everyone else; initiated_only / repatriation_pending / seasonal / mourning_period / gender_restricted_male / gender_restricted_female / custom all DENY (fail closed - no verified user attribute to grant them; the date-windowed types still lift automatically once their window passes); elder_approval_required / under_consultation route to a non-blocking requires_consultation result. Steward grants + every deny are captured in icip_access_log with the reason. Verified in isolation for all types. NOTE: the primary staff show-page gate (AtomExtensions AccessFilterService) does not yet consult this ICIP check - wiring it (ideally via a shared extracted access service) is the remaining step for full staff-view enforcement; DisclosureGate already withholds restricted records from public surfaces, and the API + share-link + research gates already honour checkAccess.
