# Heratio - Accessibility Statement

**Version:** 2.8.3
**Date:** 27 October 2026
**Standard:** WCAG 2.2 Level AA (self-assessed)
**Author:** The Archive and Heritage Group (Pty) Ltd

## Our Commitment

Heratio is committed to ensuring digital accessibility for people with disabilities. We continually improve the user experience for everyone and apply the relevant accessibility standards.

## Conformance Status

Heratio aims to conform to the **Web Content Accessibility Guidelines (WCAG) 2.2 at Level AA**. These guidelines explain how to make web content more accessible to people with a wide range of disabilities.

This is a self-assessment. Heratio has not yet had an independent accessibility audit, and no VPAT or Accessibility Conformance Report has been published. Automated testing finds only part of what WCAG covers, so Heratio does not claim full conformance until an external audit confirms it.

## Accessibility Features

### Structural Accessibility
- **Skip navigation** link to bypass repetitive content
- **ARIA landmarks** for screen reader navigation: banner, main, navigation, complementary, contentinfo
- **Language and text direction** set on the `<html>` element (supports RTL languages)
- **Semantic headings** with correct hierarchy (h1 > h2 > h3)
- **Table headers** with `scope` attributes (auto-injected)

### Keyboard Accessibility
- All interactive elements reachable via **Tab** navigation
- **Visible focus indicators** (3px blue outline) on all interactive elements
- **Escape key** closes open modals and dropdowns
- Keyboard shortcuts: **Ctrl+Shift+V** (toggle voice), **Ctrl+Shift+H** (voice help)

### Dynamic Content
- **ARIA live region** for announcing dynamic content changes to screen readers
- **`ahgAnnounce()`** function for programmatic screen reader announcements
- **`ahgFocusTo()`** function for programmatic focus management
- **Collapsible facets** with `aria-expanded` and `aria-controls` attributes
- **Form validation** linked to error messages via `aria-describedby`
- **`aria-invalid`** automatically synchronized with Bootstrap `.is-invalid` class

### Visual Accessibility
- **Colour contrast** is checked automatically against the AA minimum (4.5:1 for normal text). Theme colours an administrator chooses for the header, description bar, footer, card headers, buttons and sidebar are shaded where needed so their text reaches 4.5:1
- **Respects `prefers-reduced-motion`** for users sensitive to animation
- **High contrast mode support** via `forced-colors` media query
- **Responsive design** - works across desktop, tablet, and mobile

### Assistive Technology
- **Voice commands** (optional) - navigate, search, dictate, and describe images by voice
- **Text-to-speech** (optional) - hover-read buttons and links
- **AI image description** (optional) - generate image descriptions via local LLM (LLaVA)
- **Screen reader compatible** - tested with NVDA and VoiceOver

## Known Limitations

- The automated scans cover the pages listed below. Other pages, particularly less-used admin screens, have not been checked and may have contrast, labelling or target-size failures.
- No manual audit has been carried out: keyboard-only and screen-reader walkthroughs, zoom and reflow at 400%, and the meaning of alternative text are not yet assessed.
- Third-party embedded content (for example the IIIF, 3D and video viewers, and the Google Translate widget) may have its own accessibility limitations.
- PDF documents generated by the system may not be fully accessible; alternative formats are available on request.

## Automated Testing

Every night, and on demand, **axe-core** runs through Playwright with the WCAG 2.0, 2.1 and 2.2 A and AA rule sets against:

- the main public pages: home, browse, login, a published record and this statement;
- the main staff pages, signed in: browse, authority browse, settings, export, data migration, the error log and the dropdown manager.

The suite is `tests/e2e/05-ui-components/accessibility.spec.ts`. The run fails on a regression: any critical or serious violation that is not listed in `tests/e2e/05-ui-components/a11y-baseline.json`, which lists none.

On 27 October 2026 every scanned page was brought to no critical or serious violations. The fixes: theme colour pairs shaded to 4.5:1 (the description bar measured 3.09:1), the active filter in browse lists (white on light grey, 1.3:1), light badges given dark text, inline code and warning text darkened, links in running text underlined, 24px targets for result titles, and names for icon-only buttons and unlabelled form fields. Earlier in October the shared header and footer were corrected: the search box's ARIA role, footer text contrast, footer link target size, and the green used for record links and badges.

Automated tools find only part of what WCAG covers, so these results support the self-assessment; they are not a conformance claim.
