# v1.154.720 (2026-09-05)

fix(privacy): a barcode that passes Luhn by chance can no longer assert that the institution holds payment cards, closing #1509. The jurisdiction setting had never been written on any instance, so the per-market path had only ever run on its gdpr default - that is what #1509 was filed to exercise, and setting it found a live defect on the first run. The catalogue scan reported one record with PII, category Payment card numbers, and the record was information_object_i18n 906002: Barcode 123 1764827606 barcode. Thirteen digits that pass Luhn by coincidence, because Luhn is a single check digit and roughly one arbitrary digit run in ten passes it. It was emitted at 0.95 confidence, entered categories, and from there fed both the Article 30 draft and draftRetentionSchedule, which persists a proposal per category with NO human gate - so an archival barcode was one DPO click from becoming a retention rule for payment card data. Luhn is a typo check, not proof of cardness. What distinguishes a card is the issuer prefix, so a card may now assert only when it carries one; a Luhn-passing number without one drops to 0.40 and bands review, still shown because a reviewer should see a card-shaped number, but structurally unable to declare a category. Same validated rule as the checksum-failed national identifier at v1.154.717, which the card path was never covered by. The issuer table was checked against fifteen PUBLISHED vendor test numbers - Visa 13/16/19, Mastercard 5x and the 2221-2720 series, Amex, Discover, JCB, Diners and UnionPay - rather than against values this implementation produced, because testing a checksum with its own output proves nothing. All fifteen match; the barcode and random digit runs are rejected. COUNTER RENAMED: the autopilot reported anything barred from the categories as custom_term_hits, which stopped being true at v1.154.717 when checksum failures started landing there too. A barcode counted as a custom term hit is the same shape of wrong answer as a barcode counted as a payment card. Now review_hits and review_records, with the old keys kept as aliases. Verified end to end rather than reasoned about: the setting resolves, the catalogue scan now returns no categories and no retention proposals, the ROPA draft no longer claims payment cards, and a scan of all 9,588 catalogue rows finds exactly one issuer-valid card - the published Visa test number 4111 1111 1111 1111, in a record whose own text opens SYNTHETIC DEMONSTRATION RECORD - NOT A REAL PERSON. 1083 Package tests pass, up from 1073, and 286 Feature tests pass.
