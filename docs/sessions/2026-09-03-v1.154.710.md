# v1.154.710 (2026-09-03)

fix(privacy): PII scan criteria - an unvalidated finding can no longer become a compliance assertion, and an unconfigured market no longer detects nothing. Settings were read from ahg_setting, a table that does not exist, behind a hasTable guard that swallowed the failure, so privacy_jurisdiction silently stayed gdpr forever, the Article 30 controller name never appeared, sparql bearer auth could never succeed, and ai-compliance retention was always 7 years. All now read ahg_settings via AhgSettingsService, and the Data Protection form can set the two privacy keys for the first time. That is what made the rest urgent: both defects below were unreachable only because the setting was unwritable, and this release is what makes them reachable. JURISDICTION: a configured code with no pattern set was handed to collectors whose isset guards skipped it, so phone and national-ID detection returned zero and reported success. Worse than silent, the jurisdiction-independent card detector then inherited the span, and a 13-digit SA ID passes Luhn, so an ID was reported AS A PAYMENT CARD at 0.95 and would reach the ROPA as Payment card numbers. The registry holds ndpa and kenya_dpa alongside pipeda, all active, so three of six live jurisdictions were affected, and Nigeria and Kenya are named target markets. jurisdictionsToScan now derives the union from the pattern constants and widens rather than narrowing; the settings select reads the registry and labels codes with no market-specific patterns; uk_gdpr seeded. The registry decides what is offerable, never what is scannable. CUSTOM TERMS: operator watchlist hits emit at 0.90, which banded as high, added 25 to the risk score each time, entered categories_of_data on an Article 30 record and persisted one RetentionProposal per category for a DPO to accept, so one common surname made every record containing it high-risk and manufactured a data category. 0.90 is confidence in the MATCH; that the word is sensitive is the operator assertion. Now banded review before confidence is consulted, out of the tallies and the score, reported as custom_term_hits alongside the categories rather than inside them. BANDS: the controller advertised four bands including critical, which this path cannot emit since it belongs to privacy_breach.severity, while the view ignored that map and defined its own three, so a new band would have rendered as an unstyled grey badge. Extracted RISK_BANDS and a pure static bandFor(); the view renders from the passed map; a test walks 8 types x 12 confidences asserting every band it can emit has a colour. Verified against data rather than code: all 17 stored findings reclassify identically, so no false artefact exists here and nothing needs repair. Also indents 13 markdown bullets inside the DPIA and retention PROMPT heredocs by one space: they begin with a hyphen at column 1, which hooks/pre-commit gate 3 reads as a pasted unified diff, so this file could not be committed at all since that gate shipped. Whitespace only, inert to the model reading the list. 40 package tests, up from 14, and 256 Feature tests pass.
